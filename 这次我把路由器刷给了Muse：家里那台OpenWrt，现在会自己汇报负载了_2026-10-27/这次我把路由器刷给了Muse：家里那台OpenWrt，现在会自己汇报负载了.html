这次我把路由器刷给了Muse：家里那台OpenWrt，现在会自己汇报负载了

Muse 玩到现在，桌面上的小圆屏、口袋里的挂件我都做过了。但上个礼拜我突然反应过来一件事——我一直忽略了一台最适合当 Muse 身体的设备。

就是我家那台刷了 OpenWrt 的软路由。

想想看：它 24 小时在线、天生就知道全家谁在上网、流量跑了多少、哪个服务挂了。这不就是 AI 助手梦寐以求的“身体”吗？以前我想查家里网络，得开电脑 SSH 上去敲命令；现在我希望的是——躺在沙发上问一句，它自己答。

翻了一圈 GitHub，发现已经有人把这条路趟通了。一个叫 burndown 的开发者写了 luci-muse-gadget，把 Meta 官方的 Muse Gadget SDK Linux 客户端塞进了 OpenWrt，还配了个 LuCI 管理页面。我照着折腾了大半个晚上，成了。这篇记一下全过程和坑。

01
先说这项目干了件什么事

Meta 官方的 Muse Gadget SDK 只认树莓派和 Debian：安装脚本依赖 apt 和 systemd，配对还得有蓝牙。OpenWrt 上一个都没有——它是 procd 管服务、musl 做 C 库，连 Python 都是精简版。

这个项目解决的正是这三件事：

让 SDK 在 procd + musl 的环境里跑起来
把唯一需要蓝牙的配对步骤拆出来，借一台带蓝牙的 Linux 机器做一次就行
把路由器能提供的能力做成可勾选的命令，而不是只给 Muse 一个低权限 shell

装好之后的效果：路由器会作为一个 gadget 出现在你的 Muse App 设备列表里。Muse 能看路由器状态、局域网设备、流量和日志，你允许的话它还能重启服务、甚至重启路由器。

仓库地址：GitHub 搜 burndown/luci-muse-gadget，Apache 2.0 开源。作者实测环境是 ImmortalWrt 25.12.1。

02
动手前先盘一下家底

我是奔着踩坑去的，结果第一步就被拦住了：家里的 Netgear 顶多刷个老固件，跑不动 Python。最后是拿 PVE 里的虚拟机路由（x86_64）装的。

1一台 OpenWrt / ImmortalWrt 路由器，能 SSH，能上网，装了 LuCI
2路由器上得有 50MB 以上的空间——Python 3 加依赖要吃 30MB 左右，空间不够的别硬来
3一个 Muse SDK token（gadgets.muse.ai 生成，mgst_ 开头那个）
4一台带蓝牙的 Linux 机器，只在配对那几分钟用。没有的话几十块买个 USB 蓝牙适配器插任意 Linux 机上也行
5手机装好 Muse App

我一开始没细看 README，拿着笔记本（Windows）就想配对，卡了十分钟才看到那行“macOS 和 Windows 不行”。别学我。

03
装它

把仓库下载到电脑，拷到路由器上跑安装脚本，三条命令的事：

git clone https://github.com/burndown/luci-muse-gadget.git scp -O -r luci-muse-gadget root@路由器地址:/tmp/ ssh root@路由器地址 'sh /tmp/luci-muse-gadget/install.sh'

脚本会自动装 python3、cryptography 这些依赖，下载官方 SDK，把服务脚本和 LuCI 页面都配好。我虚拟机里网速还行，整个过程十来分钟。

路由器访问 GitHub 困难的话，可以在电脑上先 clone 好官方 SDK，再用 SDK_DIR=/tmp/muse-sdk sh install.sh 指定本地副本——国内环境这个姿势更稳。

装完刷新 LuCI，“服务”菜单里会多出一个 Muse Gadget。这时候先别急着开，因为还没配对。

04
配对：整个流程里最别扭的一步

Muse 的配对靠蓝牙把设备令牌传给设备，之后设备走网络直连，蓝牙就用不上了。所以官方设计是——找台带蓝牙的 Debian 系机器，跑仓库里给的脚本：

bash pair-on-linux.sh

脚本会让你输 token（不回显），然后打开一个 10 分钟的配对窗口，屏幕上会显示设备蓝牙名，类似 MuseGadgetB19C5C。这时候拿手机：

1Muse App → 设置 → 设备，打开 Developer mode
2点右上角 +，选中那个 MuseGadget 设备
3提示“社区设备”时确认继续
4让选 Wi-Fi 就选当前网络——就算 App 最后报“连接失败”也别慌，设备本来就在线，以脚本打出来的结果为准

成功后脚本会打印一串 MUSE1: 开头的长文本，复制下来。这串东西就是“配对包”，等价于路由器在 Muse 世界的身份证。

我第一次配对死活搜不到设备，后来发现是手机上挂着 nRF Connect 把 BLE 占了——被连接状态的设备会停止广播。关掉再试就好。

05
导入、启用、选权限

回到 LuCI → 服务 → Muse Gadget，把配对包粘进 Pairing 区块导入，设置里勾 Enable，保存应用。几秒后状态应该是：Service 运行中、Paired with Muse 是。日志里蹦出 registered with the Muse，就成了。

接下来是我觉得这项目最见功力的地方——权限模型。默认给 Muse 的只有 SDK 四个通用命令（shell、文件读写、健康状态），而且 shell 是降权到 muse 账号跑的，这个账号在路由器上连 /etc/shadow 都读不到。

真正想让它“看家”，要在 Capabilities 里勾具名命令，每一条都是写死参数、root 执行、可勾选的：

router.status——型号、负载、内存、接口状态
router.clients——局域网里谁在线（DHCP+ARP）
router.traffic——各接口流量
router.services / router.log——服务状态、系统日志
router.ping / router.dns_lookup——从路由器发起连通性测试
router.service_control——重启你白名单里的服务
router.reboot——重启路由器，必须带 confirm=true

只读 ≠ 没有隐私。clients 会把家里设备的主机名和 MAC 交给 Muse 云端，log 里可能有敏感信息。按需勾，别全选。

06
实测：问它一句

配完之后我第一句话问的是：“局域网里现在哪些设备在线？”两三秒后它把设备名一个个报出来，跟我 SSH 上去 ip neigh 看到的对得上。然后又问了负载、让它从路由器 ping 了一下外网 DNS，都正常。

比较妙的体验是你完全感觉不到“命令”的存在。上一代玩法是我对着路由器敲命令看数字；这一代是我说人话，它自己去调 router.status 然后把结果讲成人话。工具还是那些工具，交互换了个时代。

家里断网的时候，以前我第一反应是掏手机连路由器后台；现在第一反应是问问 AI——它会告诉我哪个服务挂了，需不需要重启。

07
几笔账，说点实话

关于用途。路由器装 Muse 的实用价值比桌面摆件高。桌面贾维斯是个玩具，路由器是真干活的：看网、排障、盯流量。配合 service_control，很多“重启大法”能解决的故障以后连人工都不用。

关于隐私。这是绕不开的一笔：你等于主动把家里网络的观察权交给一个云端 AI。作者文档里写得很坦诚，甚至列了 muse 账号实测能读什么不能读什么——这种把丑话说在前面的文档，现在不多见了。但决定权在你：不想给就只勾 status 和 ping，通用 shell 关掉。

关于门槛。比 ESP32 那套高不少。得有能刷 OpenWrt 的路由器、得会 SSH、还得凑一台带蓝牙的 Linux 机器。适合手里本来就有软路由的人，专门买设备来玩不建议。

关于延迟。问一句等两三秒，比起本地 dash 工具还是慢。它赢在“不需要你主动去看”——你人不在家也能问，这就算赢。

08
写在最后

到这篇为止，Muse 系列 dashboard 凑齐了三块：桌面（ESP32 小圆屏）、挂件、还有这次的路由器。做下来最大的感受是——选什么硬件不重要，重要的是这个硬件能不能成为 AI 的眼睛和手。路由器恰好是家里最合适的那个：永远在线，永远知道最多。
