👁️ 插件一：ModLens —— 给AI装一双"慧眼"

🤔 是什么？

DeepSeek V4系列旗舰模型是纯文本模型，看不了图片。你在DSH里粘贴一张截图，AI只会一脸懵。ModLens的解法很巧妙：你把图片粘贴进聊天框，它自动转发给一个视觉模型（Gemini、Qwen-VL、Claude等都行），视觉模型把图片内容解析成结构化的JSON证据——包括OCR文字、页面布局区域、实体和语义关系——再把这些信息喂回给DeepSeek，让它基于图片内容继续推理。

说白了，ModLens就是个"视觉外挂"。它不改变DeepSeek本身，而是在图片和文本模型之间架了一座桥。

💡 "不是让模型学会看图，而是让图变成模型能读的文字。"

这和普通OCR工具有本质区别。OCR只认字，ModLens保留的是元素之间的位置关系和语义。比如一张网页截图，它不只告诉你"这里有个按钮写着提交"，还会告诉你"这个按钮在表单右下角、输入框的下方"，模型据此能理解整个页面结构。

⚡ 能干什么？

• 直接粘贴图片或截图，AI就能"看懂"并回答

• 报错截图丢进去，AI自动分析错误原因

• UI设计稿还原度检查——页面写完截个图，让AI对比设计稿找差异

• 文档、流程图、手写笔记的识别和解读

• 配套的ModSearch还能扩展搜索源，接入Firecrawl、Tavily甚至Twitter搜索

🔧 怎么用？

安装就一行命令：

npx -y @deepseek-ai/dsh plugin --profile web add @liustack/modlens@3.18.3

装完之后，你需要给它配一个视觉引擎。最省心的方式是申请一个免费的Gemini API Key（Google AI Studio三分钟搞定，不用信用卡），每次识图只要5-10秒。如果连注册都不想，装个Antigravity CLI扫码登录就行，就是慢一点（15-45秒）。

ModLens内置6个视觉提供方，还能复用你本地Claude Code、Codex等CLI的登录态。多个引擎自动组成故障转移链——快的先上，挂了就换下一个，第一个出结果的赢。

适合谁

前端开发者（截图检查还原度）、经常需要分析报错截图的人、需要从图片中提取信息的研究者。说白了，只要你有"让AI看看这张图"的需求，就值得装。

仓库：github.com/liustack/modlens ｜ 据GitHub数据，截至8月21日该插件在多个榜单中位列视觉类第一

🌐 插件二：dsh-browser —— 让AI直接操控你的浏览器

🤔 是什么？

一个DSH桥接插件加一个Chrome MV3扩展的组合。装好后，DSH可以直接操作你正在使用的真实Chrome浏览器——读取网页内容、点击按钮、填写表单、滚动跳转。关键是：你浏览器里的登录状态、Cookie、Session全部保留，不需要让AI重新登录任何账号。

你可能会想：浏览器自动化不是早就有了吗？Selenium、Puppeteer不都能干？没错，但dsh-browser有两个杀手锏。

第一，零视觉依赖。传统方案靠截图+视觉模型去猜按钮在哪，又慢又贵还容易点错。dsh-browser的做法是把网页转成结构化文本，给每个按钮、输入框、链接编个号，AI直接根据编号操作。纯文本模型也能干，5秒搞定的事不需要等视觉模型45秒。

第二，真实登录态。它连的是你正在用的Chrome，不是另开一个无痕窗口。你在淘宝、后台管理系统、企业微信网页版里的登录状态全都在，AI操作的就是你已经登录好的页面。这对需要登录后才能操作的自动化场景来说，是刚需中的刚需。

🔒 安全细节

密码、银行卡号等敏感字段会被自动遮蔽，不会进入模型侧。不过还是要提醒：让AI操控浏览器权限很大，别在存了重要账号的环境里乱试。

⚡ 能干什么？

• 自动化数据采集：登录后台、翻页、抓取表格数据

• 批量表单填写：重复性录入工作一键搞定

• 网页操作自动化：定时签到、自动下单、内容发布

• Web应用测试：让AI模拟用户点击流程，自动跑测试用例

• 任何"我每天都要在网页上重复做"的操作，理论上都能交给它

🔧 怎么用？

dsh-browser比普通插件多一步——除了装DSH插件，还要在Chrome里加载一个本地扩展。官方提供了一键安装脚本：

curl -fsSL https://raw.githubusercontent.com/Lum1104/dsh-browser/refs/heads/main/scripts/install.sh | bash

脚本会自动装好DSH桥接插件，然后引导你在Chrome里加载MV3扩展。装完在Chrome侧边栏能看到连接状态，显示"已连接"就可以用了。

嫌麻烦？直接把GitHub仓库地址丢给DSH，让AI自己读README帮你装，装完它会提示你重启。

适合谁

运营和增长（批量发内容、采数据）、测试工程师（自动化Web测试）、任何有网页重复操作痛点的人。对比Selenium类工具，它的优势是不用写脚本，用自然语言指挥AI操作就行。

仓库：github.com/Lum1104/dsh-browser ｜ 据《DeepSeek Harness开源插件破万，实测推荐7个实用插件》（网易新闻）报道，该插件在浏览器自动化品类中热度领先

👥 插件三：Agent Teams —— 一句话拉起AI协作团队

🤔 是什么？

一个多Agent协作编排插件。你可以创建多个专业化Agent，给它们分配角色和任务，它们会自动拆分任务、感知依赖、按DAG（有向无环图）调度执行，还支持任务中断后的冷恢复。据澎湃新闻报道，dsh-agent-teams目前已经达到了产品级成熟度，不是玩具。

如果你用过DSH自带的subagent功能，可能会觉得"不就是派子任务吗"。区别在于：原生的一次性子代理是"干完就完"，没有编排、没有状态管理、出错了没法续。Agent Teams把这件事升级成了可治理的工程系统。

🐋 "一个人干叫工具，一群人协作才叫团队。AI也一样。"

⚡ 核心能力

• 一句话建队：告诉它你要干什么，自动拆出角色和分工

• DAG可视化：任务依赖关系画成图，谁先谁后一目了然

• 自动调度：能并行的并行，有依赖的排队，不需要你手动排期

• 冷恢复：跑到一半挂了，从断点继续，不用从头再来

• 共享状态：Agent之间可以读写共享数据，传递中间结果

• 配套GUI版本（dsh-agent-team-gui）支持持久化编排、运行历史和用量统计

举个实际场景。你说"帮我做一个用户登录系统的技术方案"，Agent Teams可以自动拆成三个角色：

📋

需求分析师

先分析你的模糊需求，输出结构化需求文档，传给架构师

🏗️

架构师

拿到需求文档后设计技术架构、选技术栈、画组件图，传给开发者

💻

代码实现者

根据架构文档写出示例代码，最终汇总成完整方案

整个过程自动流转，你只需要说一句话和最后审核结果。如果架构师觉得需求不清楚，它还能把任务打回给需求分析师补充——这不是流水线，是真正有反馈回路的协作。

🔧 怎么用？

dsh plugin --profile web add @nanmicoder/dsh-agent-teams

安装命令来自Awesome DSH Plugin精选榜单。装完重启dsh web，在对话里直接说"帮我组建一个XX团队做XX事"就行。想要图形界面的话可以再装 dsh-agent-team-gui，支持DAG画布拖拽编辑。

适合谁

需要处理复杂多步骤任务的开发者和团队、想搭建自动化工作流的人、对多Agent协作感兴趣的技术爱好者。对比CrewAI、AutoGen等框架，它的优势是原生集成在Harness生态里，不用另起炉灶，和其他插件能联动。

仓库：github.com/NanmiCoder/dsh-agent-teams ｜ 据澎湃新闻源码分析，该插件已达"产品级成熟度"

📊 三个插件横向对比

ModLens

解决痛点：纯文本模型看不了图

技术路线：视觉模型转结构化文本 → 喂回文本模型

同类对比：比OCR多了语义理解，比直接用多模态模型更省钱灵活

上手难度：⭐ 一行命令+一个免费Key

dsh-browser

解决痛点：AI无法操作需要登录的网页

技术路线：Chrome扩展+结构化文本，零视觉依赖

同类对比：比Selenium不用写脚本，比Playwright自带登录态

上手难度：⭐⭐ 需额外装Chrome扩展

Agent Teams

解决痛点：单Agent处理复杂任务效率低

技术路线：多角色编排+DAG调度+冷恢复

同类对比：比CrewAI更贴近Harness生态，比原生subagent更可治理

上手难度：⭐⭐⭐ 需要理解多Agent编排概念

🧊 冷静一下：插件虽好，但别急

吹完了，说几个你需要知道的现实问题。

第一，Harness还在rc阶段。目前版本是v0.1.0-rc.8，API和配置可能随时发生破坏性变更。今天能跑的插件，明天升级后可能就挂了。用于生产环境请三思，先固定版本号。

第二，社区插件质量参差。2600+仓库里，有dsh-agent-teams这样的精品，也有大量"电子宠物""俄罗斯方块""复古QQ皮肤"这样的玩具。开源生态的通病——没有审核，质量靠社区自治。安装前最好去仓库看一眼源码和最近更新时间。

第三，插件=在你的机器上跑第三方代码。它能读你的文件、用你的凭证、访问网络。工具审批并不沙箱化插件代码。别在放了密钥的目录里乱试，只装官方或高Star、源码透明的插件。

第四，TypeScript的性能天花板。对于高并发、低延迟场景，Rust写的Codex在性能上有结构性优势。DSH更适合独立开发者和中小团队快速原型，重型生产场景还需观察。

💡 "开源生态的魅力在于百花齐放，风险也在于百花齐放。尝鲜要快，上生产要稳。"

🪞 AI内观：插件生态的本质是"选择权的归还"

写完这三个插件，我最大的感受不是"哇好厉害"，而是一种更深层的触动。

想想看，以前我们用AI产品，能力是厂商给的。厂商说"这个版本支持图片"，你才能看图；厂商说"暂时不支持浏览器操作"，你就只能等着。用户是被动接受者。

Harness的"一切皆插件"，本质上是把选择权还给了用户。模型看不了图？社区有人给你做ModLens。需要操控浏览器？有人给你做dsh-browser。想要多Agent协作？有人给你做Agent Teams。你不需要等官方排期，不需要接受"我们后续版本考虑"的客套话。

8天，2600+插件，30万+Star。这不是DeepSeek一家公司的胜利，是开放架构对封闭生态的降维打击。就像Android之于iOS——Google不做所有App，但它让所有人都能做App，最终生态自己长出了一切。

据澎湃新闻的分析，DeepSeek选了"组装"路线——开放生态、社区驱动、广度优先；OpenAI选了"嵌入"路线——把Agent装进产品、企业级深度、深度优先。它们不是在争同一个市场，而是在共同把Agent从"聊天框里的实习生"变成"能嵌入任何产品的隐形大脑"。

对我们普通人来说，这意味着什么？

意味着AI能力的获取成本正在趋近于零。以前需要一个团队三个月做的事，现在一个人一下午拼几个插件就能搞定。你的竞争对手不再是隔壁公司，而是那个会用插件把自己"武装到牙齿"的独立开发者。

所以，别只当围观者。选一个插件装上试试，从ModLens开始最容易——粘一张图，感受一下AI"突然能看见"的那一刻。那个瞬间，你会真正理解这场变革的分量。
