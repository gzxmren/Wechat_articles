     DSH 优化到底要装什么？    

   

     三个项目搞定：从研究、工具化到场景适配一条龙。    

 
 

     Deepseek pro的神鬼二相性性，相信大家都有所耳闻。最近各路大神找到了让pro夯爆的方法，并无私的分享出来。

   今天把这几个项目整理一遍，重点把可操作流程写清楚，让你看完就知道「我该装哪个、怎么装、装完怎么验证」。   
 
   
     

01

     

PART

   
   
    
     

一条线讲清楚前因后果

     

BIG PICTURE · 三个项目 = 一拨研究 + 一拨工程 + 一拨调优

   
 
 

   直接上一张图，把三个项目的来龙去脉讲清楚：  

 
   

  第 1 步：发现问题（xiaobright/modeltest · ⭐220）    

   

     用 V4.1b 自测套件（Python + ESP32 多模块工程）跑 V4 Pro：在 DSH minimal + max 下能拿 99/96，但同样的 WSL/max 环境切到 standard 和 PTC 只有 91/92。    

   

    第 2 步：定位问题    

   

     差异不在模型、不在 harness、不在工具——而在「首次请求的 RL 对齐 scaffold」。也就是说，给模型的第一次引导条件，决定了它整个会话的轨迹。    

   

     第 3 步：提方案（xiaobright/dsh-anchored-standard · ⭐2322）    

   

     搞了个两阶段 preset：第一次请求只给 Minimal 工具对（pwsh + read），第一次工具调用后再恢复 25 项 Standard 工具。结果：98/99（worst 98，均值 98.5），V4 Pro 直接进入 GPT-5.6 / Opus 5 同分带。    

   

     第 4 步：工具化（yjh051108/dsh-routing-suite · ⭐1897）    

   

     作者受 dsh-anchored-standard 启发，把思维模式路由做成可装可卸的工具套装——聚合了注入器、router-standard、mode-boost 三个组件，主打「任务感知自动切 persona」。致谢里点名引用了 xiaobright 的研究。    

   

     第 5 步：场景适配（SheberDavid/v4-flash-godmode-opencode-go · ⭐302）    

   

     把 dsh-router-standard 里为 Flash 标定的最优引导（w7 persona + 深度思考锚）焊死在 opencode-go 的 deepseek-v4-flash 上，专门解决 Flash「鬼模式」问题。规划深度从 2.9 万字拉到 37.5 万字。    

 
 

   一句话总结：  

 

   xiaobright 是研究员（用 modeltest 发现问题，用 dsh-anchored-standard 给出第一个实验方案），yjh051108 是工程师（把它做成可装可卸的工具包），SheberDavid 是调优师（针对 Flash 这个特定模型焊死引导）。三个项目是互补不是替代。

PART

   
   
    
     

三大机制的核心差异

     

3 MECHANISMS · 锚定 vs 路由 vs 适配

   
 
 

   三个项目解决的不是同一个问题，解决的层次不一样。把它们的核心机制摆一起看就清楚了： 

                                                                
维度锚定机制路由机制适配机制
代表项目dsh-anchored-standarddsh-routing-suitev4-flash-godmode
核心思路首次请求锚定 → 后续提升按任务切 persona把最优引导焊死
触发信号首次 tool schema模型类型 + 任务类型是否命中 Flash 模型
关键变量工具 schema、output budget、提醒注入spec/react/mixed/weak 四模式w7 persona 静态合并
目标模型V4 Pro（高分榜）Pro / Flash 通用V4 Flash（专用）
实测效果99/96 → 98/99路由 96% / 收敛 100%规划深度 13×
安装复杂度⭐（3 步）⭐⭐（5 步含 submodule）⭐（3 步）
 
 
   

     关键差异点：锚定机制解决「会话开头」的问题，路由机制解决「会话过程中」的问题，适配机制解决「特定模型」的问题。三者不冲突，可以叠加。

PART

   
   
    
     

决策树 · 按你的模型选方案

     

WHICH ONE · 30 秒选对

   
 
 

   不绕弯子，直接给你一张决策树，按你现在的模型和场景对号入座：  

 
   

     
Q1 · 你主要用 V4 Pro？    

   

     是 → 走 dsh-anchored-standard，把 99/96 拉到 98/99；否 → 看 Q2。    

 
 
   

     
Q2 · 你主要用 V4 Flash（且走 opencode-go provider）？    

   

     是 → 走 v4-flash-godmode-opencode-go，让 Flash 摆脱鬼模式；否 → 看 Q3。    

 
 
   

     
Q3 · 你想要 dsh 全套能力（注入器 + 路由 + 模式提升）？    

   

     是 → 走 dsh-routing-suite；否 → 你可能不需要 DSH 优化，先确认你用的是不是 dsh。    

 
 
   

     高阶玩法：如果你同时用 Pro 和 Flash，可以先装 dsh-routing-suite 作为底座，再叠加 dsh-anchored-standard（仅在 Pro 上生效）和 v4-flash-godmode-opencode-go（仅在 Flash 上生效）。    

   

     前提：你的 dsh 版本必须是 rc.6+，否则 v4-flash-godmode 会踩时序坑。    

 
 
   
     

04

     

PART

   
   
    
     

实操流程

     

COPY & RUN · 三个方案分步走

   
 
 

   下面三套流程都可以直接复制粘贴执行，按你的场景选一套就行。  

 

   流程 A · V4 Pro 用户（dsh-anchored-standard）  

 

   第 1 步 · 克隆 preset 仓库（GitHub Releases 也有预打包）  

 
   CMD    git clone https://github.com/xiaobright/dsh-anchored-standard.git  
 

   第 2 步 · 复制 preset 到 dsh 用户目录（二选一：base mode / zero-anchored / whoami）  

 
   CMD    mkdir -p ~/.dsh/.agent-presets && cp -r dsh-anchored-standard/preset ~/.dsh/.agent-presets/anchored-standard  
 

   第 3 步 · 编辑 settings.yaml 启用 preset  

 
   

agent-default-model:

   

provider: opencode-go   # 或其他支持 V4 Pro 的 provider

   

model: deepseek-v4-pro

   

reasoningEffort: max

   

agent-presets:

   

default: anchored-standard

 
 

   第 4 步 · 重启 dsh，新会话自动走两阶段（首次 minimal → 首次 tool call 后 promote 到 standard）  

 

   流程 B · V4 Flash 用户（v4-flash-godmode-opencode-go）  

 

   第 1 步 · 克隆仓库  

 
   CMD    git clone https://github.com/SheberDavid/v4-flash-godmode-opencode-go.git  
 

   第 2 步 · 跑一键安装脚本（Windows/macOS/Linux 三平台通用）  

 
   CMD    cd v4-flash-godmode-opencode-go && ./install.sh  
 

   第 3 步 · 编辑 settings.yaml（⚠️ 关键三行必须写对）  

 
   

agent-default-model:

   

provider: opencode-go

   

model: deepseek-v4-flash

   

reasoningEffort: max

   

agent-presets:

   

default: router-flash

 
 

   第 4 步 · 重启 dsh，提交任务即可  

 

   流程 C · 想要 dsh 全套能力（dsh-routing-suite）  

 

   第 1 步 · 克隆套装（含两个 submodule）  

 
   CMD    git clone --recurse-submodules https://github.com/yjh051108/dsh-routing-suite.git  
 

   第 2 步 · 跑一键安装（Windows PowerShell 用 .\install.ps1，Linux/macOS 用 ./install.sh）  

 
   CMD    cd dsh-routing-suite && ./install.sh  
 

   第 3 步 · 重启 dsh，新会话选择 Router Standard (experimental)  

 

   第 4 步 · 验证 dev_* 工具可用（输入下面任一命令）  

 
   CMD    dev_router_status  
 
   

     三个项目安装顺序建议：先装流程 A 或 B 单独用着；想叠加就先装 C（注入器提供 dev_* 工具），再装 A 或 B 的 preset。

验证 & 故障排查

     

VERIFY · 装对没？看这里

   
 
 

   怎么知道装对了？  

 
   

     
流程 A 装对了的标志    

   

     看 dsh 日志：第一次请求的 tool list 只有 2 个（pwsh + read 或 bash + str_replace_editor），第一次工具调用后瞬间跳到 25+ 个 Standard 工具。    

 
 
   

     
流程 B 装对了的标志    

   

     新会话启动后，看模型的 system prompt 第一行是 「You are a helpful assistant.」，后面紧跟 「Before acting, decide the task type (build or fix)...」 这五个锚。    

 
 
   

     
流程 C 装对了的标志    

   

     会话里输入 dev_router_status 能跑通，且返回 当前 persona + 路由模式。    

 
 

   常见坑 & 排查  

 
   

     
症状：装了 preset 但没生效    

   

     三件事检查一遍：① settings.yaml 里 agent-presets.default 是否写对；② preset 目录是否真在 ~/.dsh/.agent-presets/；③ dsh 版本是否 ≥ rc.6（dsh --version）。    

 
 
   

     
症状：dev_router_status 报「命令未找到」    

   

     说明注入器没装上。重新跑 install 脚本，或检查 dsh plugin --profile web list 看 injector 是否在列表里。    

 
 
   

     
症状：Pro 模型用了 v4-flash-godmode 不生效    

   

     正常现象。v4-flash-godmode 是专为 Flash 设计的（命中 isFlashModel 才生效），Pro 不受影响，会走原版路由逻辑。    

 
 
   

     
症状：想回滚到原始 DSH 行为    

   

     settings.yaml 里把 agent-presets 整段注释掉或删掉，重启 dsh 即可。原版 DSH 行为完全保留，随时切回。
