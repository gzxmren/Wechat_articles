分享一个能把 DeepSeek Harness 装进口袋的东西。

先说它要解决的那个具体问题。

你有没有过这种时刻：Agent 在电脑上跑到一半，人得出门了。地铁上你只能靠猜，猜它到哪一步了，猜它是不是卡在哪个审批上。

到家一看，卡了四十分钟。

它一直在等你点那一下。

DeepSeek Harness 这两个多月被聊烂了，但有个短板很少有人正面提：它是长在电脑上的。WebUI 只监听本机回环，你一离开那张桌子，基本等于掉线。

这个洞不大，但特别硌人。尤其是你活儿干到一半必须出门的时候。

一

这个洞，想补的人不少



补法有三种，差别挺大。

最轻的一种叫 dsh-pocket，1924 颗星。电脑上跑 dsh web，手机扫码，浏览器里就是同一屏。局域网、公网隧道、访问密码，都给你配好了，不装 App，扫完就能用。

第二种叫 dsh-mobile-apk，782 颗星。这个路子反过来——它不遥控电脑，是把 DSH 连同一个精简的 Linux 环境塞进安卓手机里，本地跑，不依赖任何主机。代价是只有安卓。

第三种，就是今天要说的 Whaleness，578 颗星。

它走的是最重的那条路：自己写一个原生 App，iOS 和安卓各一套界面，再加一个必须装在电脑上的网关插件。

我看到这个排名的时候愣了一下。

垫底的，恰好是工程量最大的那个。凭什么呢？

这个数字后面再说，先把东西讲清楚。

二

它的链路里，没有一台属于厂商的服务器



这是 Whaleness 最容易被忽略、也最值得说的一点。

整条路是这样的：手机发指令，指令到你自己的电脑，电脑上的网关插件转给 Harness，然后由你配置的模型服务去算。

三段，每一段都在你手上。

作者在 README 里写得很直白：Whaleness 开发者不提供统一的聊天中转服务器。

怎么说呢，这句声明看着平淡，其实是整个项目的立身之本。

对比一下就懂了。市面上大多数“手机远程”，要么过厂商的中转，要么直接把会话托管上云。省事，但你的 prompt、你的文件路径、你的工具输出，全都从别人家的机器上走了一遍。

这条偏偏不省那个事。

手机和电脑靠 WebSocket 直连，配对靠一次性二维码，长期凭据存在 iOS 的 Keychain 或者安卓的 Keystore 里。

出门要用，走 Cloudflare 隧道或者 Tailscale；在家就是局域网直连，填个 IP 的事。

代价也摆在这儿：网络得你自己搞定。动心之前先掂量一下这件事，因为后面所有的坑，基本都从这儿长出来。

可这恰恰是它最值钱的地方。你想想看，一个宣称“不用你操心网络”的产品，一定有人在替你操心网络——而那个人，顺手就拿走了你的数据。

反过来也一样。你把网络这一摊揽回自己手里，麻烦是麻烦了点，可数据这条路就再没人插得进来。

绕过别人家的水箱，管子自己接

三

它不是个网页壳，这一点值得单独拎出来



深蓝渐变的主界面：工作区、未分组会话、最近会话

市面上很多“手机版”，做法是把桌面网页缩一缩塞进 WebView。能用，但你摸得到它是一层壳。

Whaleness 不是。

它用 Kotlin Multiplatform 把业务层抽出来共享——协议解析、状态管理、会话投影、历史同步、文件下载状态机，这些只写一遍。

界面各写各的：安卓是 Jetpack Compose，iOS 是 SwiftUI。

作者自己的说法是，共享“业务”，不共享“UI”。

这个选择换来了什么？

轨迹页上，你能展开每一次工具调用的参数、返回值、Schema、Token 数和耗时；文件卡片能分块下载、校验完整性、预览 PDF 和代码；锁屏和灵动岛能显示“正在等审批”“已完成”。

这些东西网页壳不是做不出来，是做出来难看，而且难看到没人愿意做。

深色对话页：对话/轨迹分段、耗时与工具调用、定时任务回执

代价同样具体：两套原生 UI，等于同时维护两个 App。

它两个月迭代到 v1.7.8，一周一个版本，插件管理、定时任务、语音输入、折叠屏适配，一个一个往里填。

这个速度说明作者是真的在做。也说明这个架构重，重到换个人根本撑不住这个节奏。

你会问，一个个人项目，为什么要挑最重的那条路走？

我也想过。想来想去，大概是因为另外两条路都有人占了，而且占得挺好。

四

最值钱的那一步，是你在电梯里点了“允许”



我一直觉得，“手机远程”这个说法误导了很多人。

听起来像远程桌面：把电脑屏幕搬到手机上，你在小屏幕上戳。

其实不是。

Agent 真正卡住的地方，从来不是算力，是等人。

它问你“这个目录要不要一起删”，它问“这条命令要不要执行”，它在等你点那一下。你不在，它就干等着，一直等。

Whaleness 把这一步做进手机里了：Human Question 能提交、能取消、能自定义回答；工具审批能拒绝、能允许、能只允许这一次。

配合通知，你在电梯里花三秒点完，回去它已经跑完了。

这是整条链路上我最看重的一环。远程不是“看见”，远程是“接手”。

有一说一，这也正是它风险最高的地方，下面单独说。

人还在电梯里，拉一下线，家里的机器就动了

五

装的时候，这几个坑基本躲不掉



桌面 WebUI 左侧栏底部的「移动设备」入口

桌面端三步。




bash

dsh plugin --profile web add \

    dsh-plugin-mobile-gateway@latest

dsh web

装完重启，左侧栏多一个「移动设备」，进去打开移动网关、保持设备鉴权、运行模式设成常驻，然后生成配对二维码。

手机端扫码，连上。

坑集中在后面。

第一个，真机别填 127.0.0.1。那个地址指的是手机自己。3080 是 WebUI 端口、只监听回环，手机要用的是网关另开的 3081，地址填你电脑的局域网 IP。

很多人第一次连不上，就是栽在这。

第二个，配对码 5 分钟过期，而且一次性。过期了回桌面端重新生成，别在手机那头反复试。

第三个，3081 不要开到公网。要外网就走隧道或者 Tailscale，必须带 TLS 走 wss://。

Agent 预设：标准、ptc、极简、创造四档

第四个是版本坑：DSH 一升 rc，网关就得跟着升。0.10.3 之前有个经典报错——Cannot read properties of undefined (reading 'signal')，不是你配错了，是插件旧了。

这几个坑，官方 README 其实都写了。

写得很细，细到能看出作者自己一个个被咬过。它不假装一切顺利。

其实吧，我挺喜欢这种文档。

六

578 对 1924，这个差距值得琢磨



现在回来说那个数字。

同一件事，最重的方案 578 星，最轻的方案 1924 星，差了 3.3 倍。

我一开始以为是质量差距，翻完仓库就不这么想了。

Whaleness 20 个 open issue，作者自提 PR 在修；release 一周一个；官网、隐私政策、安装向导、图文截图，一样不缺；README 里连“安卓 Studio 里 iOS Metal 编译”这种坑都单独写了章节。

这不是个粗糙的东西。

差距在别的地方。

一是门槛。扫码网页的成本是“扫一下”，原生 App 的成本是“装插件、配网络、下 APK 或者进 TestFlight、扫码”。多出来的每一步，都会掉一批人。

二是场景。大多数人要的是“出门看一眼它跑到哪了”，不是“出门接着干一整天”。只是看一眼，浏览器就够了，装 App 反而多余。

三是分发。主流的 awesome 榜单没有收录；去 V2EX、掘金、知乎、X 站内搜名字，零命中。传播基本靠作者自己的公众号和 B 站。

扫一下，和装插件、配网络、下安装包——还是同一件事

我跟你说，第三条最要命。

东西再好，没人知道，也就等于没有。这个项目最缺的不是代码，是有人在饭桌上提它一嘴。

我非常理解选扫码的那批人。

工具的选择从来不是选最强的，是选最不折腾的。你只是想在地铁上瞄一眼进度，凭啥要装个 App 配个网关？

但我还是觉得 Whaleness 代表的方向更对。

因为“看一眼”和“接手”是两个需求。轻方案解决前者，重方案解决后者。前者的市场大十倍，这很正常。

说真的，换我在地铁上只想瞄一眼的时候，我大概率也懒得装。

七

它换走的东西，得说清楚



这里得讲一段不那么好听的话。

有个叫 dsh-xray 的项目，专门对 DSH 插件做静态能力审计，不运行、只看代码，给出 C1 到 C3 的分级。

它给网关插件 dsh-plugin-mobile-gateway 的评级是 C3，用他们的话说叫“强能力叠加敏感行为”。

依据是实的：通过 cordis.patch.yml 给 DSH 运行时打补丁；代码里有 4 处系统命令执行；构建产物里有 2 处网络服务；还会读取 SUDO_UID 环境变量。

客户端主仓是 C2，代码里有 3 处命令执行，在验证脚本里。

这个站点自己也写了一句免责：等级衡量的是能力面和透明度，不是恶意程度。

说得对，C3 不等于坏。

但你得知道自己装了什么。

它不是“一根连过去的管子”，它是“往你的 DSH 里打补丁、能起网络服务、能执行系统命令的一层东西”。

再叠上另一件事：这个 App 能切换 Harness 的权限档位，包括 danger-full-access。

也就是说——你在手机上点的那一下“允许”，执行的时候用的，是你桌面端的最高权限。

我在这一节上反复想了很久。

这不是设计缺陷，这是这个产品存在的意义本身。你就是要远程接手，那接手就得有权限。

但风险提醒不是多余的：网关只放内网；要外网就走 Tailscale，别把 3081 裸奔在公网上；权限档位平时别开满，用完调回去；配对二维码别截图发群里。

坦白讲，很多人装这类工具的心态是“先跑起来再说”。

可安全这东西，出事之前都是多余的。

我也不是想吓唬谁。只是这一类工具的权力形状，跟普通 App 不一样——普通 App 坏了，卸载就完了；它要是坏在公网上，坏的是你整台电脑。

八

回到那个洞



说个我最近老想到的类比。

遥控器刚出来的时候，卖点特别朴素：不用起身换台。

它没有复制你的客厅，也没有把你搬到电视机前。它只把一个动作——换台——传了出去。

后来我们有了远程桌面，那是把整块屏幕搬过去。带宽吃满，在手机上还是看不清，戳半天戳不准。

现在这条路走的是第三种：不传画面，传语义。

你在手机上看到的不是缩小的桌面，是“它读了哪个文件、跑了哪条命令、现在要你点哪个按钮”。

传送的东西越少，能到的地方就越远。

这句话我觉得能概括这一整类工具正在发生的事。界面在退场，意图在前移。

Whaleness 这个项目本身还没赢。578 颗星，社区里几乎没人讨论，甚至输给了一个二维码。

但它把一个问题摆到了台面上：你要的到底是“看一眼”，还是“接手”。

这两个答案，对应两种完全不同的工具。

你要是经常出门、活儿又长、经常被审批卡住，那值得装一个试试。装上之后先把网关关在内网，权限档别开满。

你要是只想在地铁上瞄一眼进度，扫码那个更省事，别折腾。

两条路都对。

只是你得先想清楚，自己要去哪儿。

最后丢两个链接：github.com/Clarklevis1995/dsh-mobile 和配套的 dsh-plugin-mobile-gateway。

别急着装。先想想你是“看一眼”还是“接手”，答案不一样，装的东西就不一样。
