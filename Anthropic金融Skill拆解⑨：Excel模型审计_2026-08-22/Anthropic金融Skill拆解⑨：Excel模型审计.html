Anthropic金融Skill拆解⑨：Excel模型审计

audit-xls × Excel 模型审计
一份模型，经不经得起审计？

✍️ 小以AI · 第一观察者

💡 第6期我们拆了估值建模（dcf-model / comps-analysis 把公司值多少钱算出来），第8期拆了投行建模（3-statement / lbo 把三张表填平、把杠杆回报算对），第10期拆了并购建模（merger-model 把 EPS 增厚稀释算平），第11期拆了估值复核（valuation-review 把一份估值审得可审计）。但所有这些模型——估值、三表、LBO、并购——底层都跑在一张 Excel 上。模型搭得再漂亮，一个硬编码、一个 BS 不平、一个跨表断链、一个单位把千当百万，结论全毁。Anthropic 把这道"审 Excel 模型"的工序拆成了一个 Skill：audit-xls。它不替你"建模型"（那是 dcf / lbo / merger / model-builder 的活），而是把"公式级检查 + 模型完整性检查 + 分模型类型 bug 库 + 分级报告"工程化。它正是第11期估值复核反复提到的"底层武器"——也是 dcf / lbo / merger / model-builder 共用的审计层。拆完你会发现，AI 在金融最稳的落点永远是"可审计"，audit-xls 正是这套可审计能力的地基——先把模型审平，再谈结论可信。一份 BS 不平、满是硬编码的模型，AI 生成得再快也是空中楼阁——国内券商质控、基金中后台、审计底稿，恰恰天天在和这些"静默 bug"搏斗。


01 / audit-xls：Excel 模型审计，从"一个数"到"可审计的底稿"

① Skill深度拆解：Anthropic原版在做什么

触发场景：用户给了"一张表 / 一个 sheet / 整个模型"，说"audit this sheet / check my formulas / find formula errors / QA this spreadsheet / sanity check this / debug model / model won't balance / something's off in my model"。明确 NOT 从零建模型——建用 dcf-model / lbo-model / model-builder，它只负责"把别人建的 Excel 模型审对"（和 valuation-review"审不建"、3-statement"填不建"同源）。

第一步：先定 scope（决定审计深度）
· selection —— 仅当前选中的区间。
· sheet —— 仅当前活动工作表。
· model —— 整个工作簿，含财务模型完整性检查（BS 平衡 / 现金勾稽 / 滚存 / 逻辑合理性）。
面向客户的 DCF / LBO / 三表 / 并购 / comps / 任何集成模型，送客户或 IC 前一律用 model 级最深的审计。

第二步：公式级检查（所有 scope 都跑）
· 公式错误：#REF! / #VALUE! / #N/A / #DIV/0! / #NAME?。
· 公式内硬编码：=A1*1.05 里的 1.05 应引用单元格。
· 邻居公式不一致：同行/列里打破模式的公式。
· off-by-one 区间：SUM / AVERAGE 漏掉首行或末行。
· 粘贴覆盖：看着像公式、实为写死值。
· 循环引用：有意或无意。
· 跨表断链：引用到被移动/删除的单元格。
· 单位/量级混用：千与百万混、% 存成整数。
· 隐藏行列：可能藏着 override 或过期计算。

第三步：模型完整性检查（仅 model scope）
· 结构：输入/公式是否分离；颜色约定（蓝=输入、黑=公式、绿=链接）是否一致；tab 顺序（假设→IS→BS→CF→估值）；日期表头跨表一致；单位一致。
· 资产负债表：资产 = 负债 + 权益（逐期）；留存收益滚存（前期 RE + 净利 − 分红 = 当期 RE）；商誉/无形资产从收购假设流出（若 M&A）。BS 不平则先量化每期缺口、追溯断点——此关不过，下游全疑。
· 现金流量表：期末现金勾稽（CF 期末现金 = BS 现金，逐期）；CF 求和（CFO+CFI+CFF = Δ现金）；D&A 勾稽（CF = IS）；CapEx 勾稽（CF 匹配 BS 的 PP&E 滚存）；WC 变动符号匹配 BS 动向（ΔAR / ΔAP / Δ存货）。
· 利润表：收入勾稽到分部/产品明细；税（税前利润 × 税率，允许递延税调整）；股数勾稽到稀释计划（期权/可转债/回购）。
· 循环引用：利息→债务→现金→利息是 LBO/三表常见有意循环，验证迭代开关存在且工作；无意的则追踪并给出断开方法。
· 逻辑与合理性：增速 >100% 无解释；利润率超行业；终值占比 TV >~75% DCF EV（黄牌）；hockey-stick 外年不现实爬坡；EBITDA 复利到第10年夸张；边界 case（0%/负增长、负 EBITDA、杠杆转负）模型崩。
· 分模型类型 bug 库：DCF（折现期 mid-year vs end、TV 未折现回、WACC 用账面价值、FCF 含利息、税盾重复计）；LBO（偿债不匹配现金清扫、PIK 利息不滚本金、管理层 rollover 未反映到回报、退出倍数套错 EBITDA（LTM vs NTM）、费用未从 Day1 权益扣）；并购（增厚稀释用错股数、协同不爬坡、PPA 不平、未计现金弃息、交易费不在 S&U）；三表（WC 变动符号错、折旧不匹配 PP&E、债务到期不匹配本金偿付、分红超净利无解释）。

第四步：出报告
· findings 表（# / Sheet / Cell·Range / Severity / Category / Issue / Suggested Fix）。
· 严重度：Critical（输出错：BS 不平、公式断、现金不勾稽）/ Warning（风险：硬编码、公式不一致、边界崩）/ Info（风格/最佳实践：配色、布局、命名）。
· model scope 加一行 summary：Model type: [DCF/LBO/3-stmt/...] — Overall: [Clean/Minor/Major] — [N] critical, [N] warnings, [N] info。
· 未问不动——先报告，按需再修。

关键设计（诚实细节）：audit-xls 的本质，是把"模型正确性"工程化。几条铁律它写得很硬：① BS 平衡第一——不平则下游全疑；② 硬编码是头号静默 bug——要主动猛搜；③ 符号约定错误（现金流出正负）极常见；④ VBA 宏驱动的计算无法纯公式审计，需单独标注。

② 对应业务流程：国内券商 / 基金，怎么审计 Excel 模型

当前工作流（以投行模型质控 / 基金估值底稿 / 财务建模复核为例）：
· 收模型：投行估值模型 / GP 估值包 / 财务模型（Excel）。耗时 0.5 天。
· 公式层检查：错误 / 硬编码 / 断链 / 粘贴覆盖。耗时 1–2 天。
· 模型完整性复核：BS 平衡 / 勾稽 / 单位 / 符号。耗时 1–2 天（最痛苦环节）。
· 分模型专项：折现期 / 敏感性 / 协同爬坡 / PPA。耗时 1 天。
· 出复核意见（findings）。耗时 0.5 天。
· 质控签发 / 上会。耗时 0.5 天。

痛点清单：
· BS 不平：plug 算错，资产 ≠ 负债 + 权益。
· 硬编码：关键假设写死在公式里，改不动、查不出。
· 跨表断链：链接到被删/移动单元格， Silent 失效。
· 单位混用：千与百万混、% 存成整数，量级错。
· 符号错：现金流出正负约定乱，WC 变动反号。
· 循环引用：无意循环导致结果飘。
· 敏感性不随输入：全格同值，接线假。
· 合理性质疑靠经验：增速/利润率/TV 占比没人系统算。

谁在做这件事：券商质控填 / 投行 VP 复核 / 基金中后台估值岗 / 审计底稿复核——典型的"高勾稽、低判断"活（判断在假设定夺，审计是苦力）。

③ AI助力效果：自动审计，把"1–2 天"压到"半天"

可以替代的环节（AI做，人审核）：
· 公式层检查：错误/硬编码/断链/单位全扫。时间：1–2天→10分钟。
· 模型完整性自动审计：BS 平衡/勾稽/符号/隐藏行列。时间：1–2天→2小时。
· 分模型 bug 库自动跑：DCF/LBO/并购/三表专项坑位。时间：1天→1小时。
· findings 自动出：severity 分级 + 修复建议表。时间：0.5天→30分钟。

可以增强的环节（人+AI协作）：
· 批量扫多个模型：一次审一摞 GP 包 / 多分部模型。
· 跨 sheet 追踪：勾稽链从源头追到断点，可视化。
· 勾稽链高亮：哪条线断了，一眼定位。

不能替代的环节（人必须做）：假设合理性定夺（人判）、符号约定 policy、上会/质控签发决策。

综合量化对比：传统 Excel 模型审计需 1–2 天；AI 辅助后 半天（含人审），效率提升约 60–70%，且硬编码 / BS 不平 / 跨表断链 / 单位混用等错误率大降。

④ 国内落地差异：工具 + 数据源 + 术语 + 监管，四道关卡

差异一：建模工具与习惯
· 国内以 WPS 为主、Excel 为辅，部分函数（如某些数组/文本函数）WPS 与 Excel 行为有差；中文环境下公式嵌套深、表头中文。
· 改造要点：兼容 WPS 函数集、识别中文表头与中文命名区域、标注跨软件不兼容公式。

差异二：数据源
· 海外 CapIQ / FactSet MCP 直连；国内万得 / Choice 以 Excel 插件拉数，跨 sheet 链接到外部数据极易断、且刷新后静默失效。
· 改造要点：链接健康度检查（断链/过期/未刷新）+ 外部数据快照固化（拉数即落静态值并标注截止日）。

差异三：术语与底稿
· 国内"试算平衡 / 勾稽（tie-out）/ 底稿 / 交叉索引 / 交叉验证"概念，标准 audit 模板无；符号约定（现金流正负）各行其是。
· 改造要点：术语映射（勾稽=tie-out、试算平衡=BS balance），符号约定 policy 内嵌。

差异四：监管与质控
· 国内券商模型质控 / 基金估值底稿 / 审计底稿留存要求严，复核须可回溯（谁审、何时、改了什么）。
· 改造要点：复核留痕内嵌，findings 表带版本与责任人，合规可回溯。

⑤ 国内对应工具现状：能"写"不"审"

国内 Excel AI（Office AI / WPS AI / 通义 等）：能"写公式 / 生成表 / 套格式"，但常漏硬编码、BS 不平、跨表断链、单位混用、符号错、分模型 bug——和 audit-xls"公式级 + 模型完整性 + 分模型 bug 库 + 分级报告"是两回事。

国内建模 / 估值系统（恒生 / 赢时胜 / 万得）：有计算与报送，但非 AI 审模型，复用靠人。

总结：国内在"AI 审 Excel 模型"上几乎空白。audit-xls 国内改造的价值，是"把模型苦力审计变成一键公式级审计 + 模型完整性审计 + 分模型 bug 库 + 分级 findings"——尤其帮国内团队避开"硬编码 / BS 不平 / 跨表断链"的质量雷。

⑥ 优化方向与目标：这个Skill国内改造的路线图

近期目标：公式层 + 模型完整性（万得拉数 → BS 平衡 / 勾稽 / 硬编码 → findings 分级）
· 万得 / Choice 拉数 → 公式级扫描（错误/硬编码/断链/单位）→ 模型完整性（BS 平衡/勾稽/符号）→ severity 分级 findings 表
· 量化目标：模型审计从 1–2 天压到半天；硬编码 / BS 不平 / 断链错误率趋零。

中期目标：分模型 bug 库 + 勾稽链可视化 + 万得 / 恒生对接
· 国产 DCF / LBO / 并购专项 bug 库（折现期 / TV 折现 / WACC / 协同爬坡 / PPA）+ 勾稽链高亮 + 双端对接

远期目标：端到端（模型进 → 审计出 → 质控签发，人只定 policy）
· 终极状态：拿到模型，系统自动出"可审计 findings + 模型完整性审计 + 分模型 bug 报告"，质控岗只定符号约定与签发。

🎯 小以观察

观察一：audit-xls 的本质，是把"模型正确性"工程化——"审"比"建"更基础
dcf / lbo / merger 是"建"，audit-xls 是"审"，且是它们共用的审计层。估值复核 valuation-review 把 audit-xls 当"底层武器"，model-builder 也靠它自检。这再次印证：AI 在金融最稳的落点，永远是"可审计"，而 audit-xls 就是可审计的地基。

观察二：硬编码是头号静默 bug，BS balance first——模型审计的两条铁律
audit-xls 把"硬编码主动猛搜""BS 不平则下游全疑"写进纪律，VBA 宏驱动计算还需单独标注。国内团队最常见的翻车，恰恰是"关键假设写死在公式里、BS 怎么都平不了"——这两关过不了，再花哨的模型也是危房。

观察三：可审计模型 = 先平后信，与 valuation-review"GP 包 untrusted"同源
信任从"模型平不平"开始——audit-xls 用 BS 平衡与勾稽链建立信任，valuation-review 用 GP 包 untrusted 建立信任。两条路都指向同一句话：AI 可以审人做的，但人给的东西要先过"可信度"这关。

小以判断：Excel 模型的 AI 审计，会从"analyst 手工勾稽"走向"一键公式级审计 + 模型完整性审计 + 分模型 bug 库 + 分级 findings"。
第一步永远是 audit-xls——先把模型审平、bug 归位、勾稽过关。
