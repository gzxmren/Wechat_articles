从零开始：300 行代码，学习搭建 Claude Code 的核心流程

最近在看一个 GitHub 项目，59k stars，叫 learn-claude-code。它的口号很抓人——"Bash is all you need"。但别被误导了，它不是用 Bash 写了一个智能体，而是说：一个 Agent 的核心，只需要一个循环 + 一个 Bash 工具，就能跑起来。

项目本身是 Python 写的，12 个渐进式 session，从零开始教你搭一个 Claude Code 风格的 Agent harness。看完源码后我意识到：Claude Code 的核心机制其实不复杂，三样东西就能搭起来。

1. Claude Code 的核心是什么

很多人以为 Claude Code 是"AI 帮你写代码"，其实它的核心机制比这更底层：

工具调用（Tool Calling）+ 上下文管理（Context Management）+ 循环执行（Execution Loop）

这三样东西搭起来，就是一个 Agent harness。Claude Code 只是在这个基础上加了代码编辑、文件浏览、终端执行等具体工具。

这个项目最颠覆我认知的一点是它的理念：智能来自模型，Harness 是你写的。

Agency ——感知、推理、行动的能力——来自模型训练，不是来自外部代码编排。

你写的不是"智能"，而是给模型一个能工作的环境：工具、知识、观察接口、权限边界。模型是司机，Harness 是车。

2. 这个项目的极简实现

项目从 s01 开始，核心就三个部分：

工具调用

s01 只给模型一个工具——bash。跑 shell 命令，看输出，再决定下一步：

TOOLS = [{
    "name": "bash",
    "description": "Run a shell command.",
    "input_schema": {
        "type": "object",
        "properties": {"command": {"type": "string"}},
        "required": ["command"],
    },
}]

不需要复杂框架，Claude API 的 tool use 本身就是标准接口。很多项目过度工程化，加了一堆抽象层，反而增加理解成本。

循环执行

最核心的一段逻辑，就 20 行：

def agent_loop(messages):
    while True:
        response = client.messages.create(
            model=MODEL, system=SYSTEM,
            messages=messages, tools=TOOLS,
        )
        messages.append({"role": "assistant", "content": response.content})

        if response.stop_reason != "tool_use":
            return  # 模型说停就停

        results = []
        for block in response.content:
            if block.type == "tool_use":
                output = TOOL_HANDLERS[block.name](**block.input)
                results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": output,
                })
        messages.append({"role": "user", "content": results})

循环的退出条件设计得很重要——AI 要明确表示"任务完成"才退出，不然会死循环。项目还加了最大轮次限制作为保险。

上下文管理

关键思路是"给 AI 看足够的上下文，但不要太多"。项目用朴素的文本拼接管理上下文：

系统提示 + 历史对话 + 工具结果

没有向量数据库，没有 RAG。但效果够用了——因为每次循环只传必要的信息。

4. 我从源码里学到的 3 个思路

思路一：Agent 的核心逻辑几十行就能跑通

s01 的代码不到 100 行，一个 while 循环 + 一个 bash 工具执行器。很多项目过度工程化，加了一堆抽象层，反而增加理解成本。这个项目证明：核心逻辑不需要框架，HTTP + JSON 就够了。

思路二：Harness 工程师的真正工作

如果你在读这个仓库，你的身份是 Harness 工程师——这不是贬义，是很强的定位：

  • • 实现工具：给 Agent 手——文件读写、Shell 执行、API 调用
  • • 管理知识：按需加载，不要 upfront 塞进系统提示
  • • 管理上下文：子任务隔离、压缩策略、防止历史淹没
  • • 控制权限：沙箱、审批流、信任边界
  • • 收集训练数据：每个 action sequence 都是下一代模型的训练信号

你不是在写智能，你是在建智能居住的世界。

思路三：Prompt Plumbing 不是 Agent

作者很犀利地批评了一类项目：

拖拽式工作流构建器、No-code "AI Agent" 平台、Prompt-chain 编排库——它们共享同一个幻觉：把 LLM API 调用用 if-else 分支、节点图、硬编码路由逻辑串起来，就以为自己在"构建 Agent"。

这不是 Agent，这是披着 LLM 外衣的 GOFAI（Good Old-Fashioned AI）。复杂的是把 Agent 做到 production-ready，不是核心机制本身。

5. 怎么用到自己的工作流里

这套机制可以迁移到任何需要"AI + 工具"的场景：

  • • 自动化运维：AI 读日志 → 调用工具分析 → 判断是否需要报警
  • • 数据处理：AI 理解需求 → 调用 SQL/脚本 → 验证结果
  • • 内容生产：AI 规划 → 调用搜索/写作工具 → 审核输出

核心都是同一个模式：给 AI 工具 → 看结果 → 再决定下一步。

结语

如果你也在做 AI 相关的项目，建议看看这个项目的源码。入手路径：先看 README.md 理解 harness engineering 的理念，再跑 python agents/s01_agent_loop.py 看核心循环。

不是要用它，而是理解它的设计思路——Claude Code 的核心机制其实很简单，复杂的是把它做到 production-ready。
