Garry Tan 是谁？

Garry Tan 是 Y Combinator 的现任总裁兼 CEO。

YC 是全球最顶尖的创业加速器，Airbnb、Stripe、Coinbase、Instacart、Dropbox——这些你听过的公司，都是 YC 出来的。

在 YC 之前，Garry 是 Palantir 最早期的工程师之一，后来联合创办了 Posterous（卖给了 Twitter），还亲手搭建了 YC 内部社交网络 Bookface。

典型的那种「技术出身的创始人」。

2026 年，他做了一件让很多人没想到的事：把自己每天用的 AI 编程工具包，整个开源了。

项目叫 gstack。GitHub 地址：https://github.com/garrytan/gstack

810 倍这个数字是怎么来的？

Garry 做了一件很极客的事：把自己 2026 年的代码产出，和 2013 年（他在 YC 搭建 Bookface 那年）做了严格对比。

衡量维度不是原始代码行数，而是「逻辑代码变更量」——排除 AI 批量生成导致的行数虚高，只看真正有意义的逻辑改动。

结论：2026 年的日均逻辑代码产出，是 2013 年的 810 倍。

年化对比更夸张：2026 年截止 4 月 18 日，产出量已经是 2013 年全年的 240 倍。

他补了一句：「AI 写了大部分代码。重点不是谁打的字，是什么东西上线了。」

这 810 倍背后，是 gstack。

gstack 是什么？

一句话：把 Claude Code 变成一支虚拟工程团队。

Claude Code 你可能用过——Anthropic 出的 AI 编程命令行工具。单独用的时候，它是一个能干的万能助手，但缺乏分工。你让它做设计，它可能顺手把代码也改了；你让它审代码，它可能顺手重构一堆不相关的东西。

gstack 的思路是：给 Claude Code 装上 23 个专业角色，每个角色有自己明确的职责边界：

23 个专家，全是 Markdown 写的 slash 命令，MIT 开源，免费。

一次完整开发流程是什么样的？

Garry 在文档里给了个例子，具体展示了这套系统怎么运转。

场景：你想做一个日历日报应用。

你不是直接开始写代码，而是先跑 /office-hours。

Claude 不会立刻动手，而是开始问你六个问题：

  • 你现在准备会议具体卡在哪里？（要具体例子，不要假设场景）
  • 这个问题多久发生一次？
  • 你试过什么解决方案，哪里还不够？

你描述完，Claude 的回答是：

「你以为你要做的是『日报应用』，但你描述的其实是一个 AI 私人助理。」

然后它列出你没意识到的 5 个功能点，挑战了你 4 个前提假设，给了 3 种实现路径和工时估算，建议先做最窄的版本，明天就能上线。

接下来你跑 /plan-ceo-review，它读刚才生成的设计文档，做 10 维度审查。

你跑 /plan-eng-review，它画数据流 ASCII 图，列边界情况，写测试矩阵。

你说：批准，开始实现。

8 分钟后：2400 行代码，横跨 11 个文件。

你跑 /review，自动修了 2 个问题，1 个竞态条件让你确认后修。

你跑 /qa https://staging.myapp.com，它打开真实浏览器，点完所有流程，找到并修了一个 bug。

你跑 /ship，测试从 42 个变成 51 个，PR 开好了。

从零到 PR，8 个核心命令。

安装只需要 30 秒

打开 Claude Code，粘贴这一行：

ounter(linegit clone --single-branch --depth 1 https://github.com/garrytan/gstack.git ~/.claude/skills/gstack && cd ~/.claude/skills/gstack && ./setup

Claude 会自动完成剩下的配置。

如果你在用 OpenClaw（那个可以把 Claude 部署到 Telegram/WhatsApp 的 AI Agent 框架），gstack 也直接支持。OpenClaw 通过 ACP 启动 Claude Code session，gstack 所有技能在 session 里直接可用。

Garry 在 README 里专门写了 OpenClaw 集成指南，把它安装到 OpenClaw Agent 后，你就可以直接用自然语言触发：「对这个 repo 跑安全审查」，系统自动启动 Claude Code 跑 /cso。

gbrain：给 AI 装上真正的长期记忆

gstack 解决的是「AI 怎么干活」的问题。

Garry 同期开源的另一个项目 gbrain（https://github.com/garrytan/gbrain），解决的是「AI 怎么记住东西」的问题。

现在大多数 AI 助手是金鱼记忆——每次对话从零开始，你的项目背景、你的偏好、你昨天讨论过的决策，下次打开又得重新说一遍。

gbrain 是一个专门给 AI Agent 用的持久化知识库。Garry 自己的 gbrain 里现在有：

  • 17,888 页文档
  • 4,383 个人物档案（他接触过的创业者、投资人）
  • 723 家公司档案
  • 21 个自主运行的定时任务

这个知识库在 12 天内搭起来，现在驱动着他在 OpenClaw 和 Hermes 上运行的所有 AI Agent。AI 在他睡觉时，持续消化他的会议记录、邮件、推文、语音通话，自动更新数据库。

技术上，gbrain 底层是 PostgreSQL——可以用 PGLite 本地运行（零账号、零网络，30 秒初始化），也可以接 Supabase 云端（跨设备同步）。

gstack 提供了 /setup-gbrain 命令，选择你的方案，90 秒以内配好。

为什么这两个项目值得认真看？

不只是因为 Garry Tan 名气大。

而是因为它们代表了一种和多数人完全不同的 AI 使用方式。

多数人用 AI 的方式是： 想到什么问什么，AI 给一个回答，用了就结束。每次重头开始，没有积累。

gstack 的逻辑是： 把 AI 使用结构化成可重复的开发流程——先强迫自己想清楚（/office-hours），再规划（/plan-*），再实现，再审查（/review），再测试（/qa），再发布（/ship），再更新文档（/document-release）。每步有对应的专家角色，有明确的输入输出，有上下游衔接。

gbrain 的逻辑是： 把 AI 使用变成持续积累的过程——不是每次从零开始，而是在一个不断增长的知识库上工作。AI 越用越了解你，越用越有用。

这两件事合在一起，大概就是 810 倍的真正来源。

不是 AI 更聪明了，而是用法变了。

一个细节：gstack 还在更新

项目发布不到两个月，已经有了完整的：

  • /pair-agent：跨 AI 多智能体协作，把浏览器共享给多个 AI（Claude、Codex、OpenClaw 都支持）
  • /cso：安全审计，OWASP Top 10 + STRIDE，17 项误报过滤规则
  • /design-shotgun：生成 4-6 个设计方案变体，视觉对比，迭代挑选
  • /design-html：把选好的设计稿转成可直接上线的 HTML（不是 demo，是 shippable 的）
  • gstack-model-benchmark：同一个 prompt 跑 Claude、GPT、Gemini，对比延迟、Token 消耗、质量

Garry 在 README 末尾说：他们在 YC 招人，「想用 AI 编程速度做真实产品的工程师」——这大概也说明了 gstack 不是实验性项目，是他们自己每天在用的生产工具。
