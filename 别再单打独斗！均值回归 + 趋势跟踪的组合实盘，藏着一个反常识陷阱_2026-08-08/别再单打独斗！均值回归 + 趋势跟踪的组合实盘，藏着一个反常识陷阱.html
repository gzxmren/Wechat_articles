引言

很多刚入门量化的朋友都听过这样一句话：把两个「性格相反」的策略组合在一起，就能实现「1 + 1 > 2」的分散化收益。听起来很美，但真的做回测时，结果往往和想象中不一样。

本文用 26 年的 SPY（标普 500 ETF）日线数据，把两个经典策略——RSI(2) 均值回归和 50/200 SMA 均线交叉趋势跟踪——组合在一起，前后尝试了两种不同的组合方式。结论有点出乎意料：「组合两个策略」这句话本身，其实隐藏了一个比「组合」更重要的设计决策。

如果你正在学 Python 做量化回测，这篇文章能帮你避开一个非常隐蔽的坑。

一、先看两个策略的「性格」

在组合之前，先理解为什么它们「看起来」适合搭配：

  • • 均值回归（RSI(2)）：典型的「高抛低吸」。它的交易盈亏分布是左偏、高峰厚尾（峰度高达 27），也就是大量小额盈利，偶尔来一次惨烈的大亏损。它交易频繁，进出通常只在几天之内。
  • • 趋势跟踪（SMA 50/200 交叉）：典型的「追涨」。盈亏分布是右偏、薄尾，也就是大量小额亏损，偶尔来一次超级大赢家。它持仓周期长达数周甚至数月。

一个「快进快出」，一个「慢工出细活」，盈亏形态几乎相反。理论上，这正是分散化最该奖励的搭配。于是我们动手测了——测了两次，因为第一种组合方式问的其实是错误的问题。

补充一个小知识：RSI(2) 是 Larry Connors 推广的超短周期 RSI，因为窗口极短，指标非常敏感，常用于捕捉短期超卖反弹，是均值回归策略里的经典用法。

二、尝试一：资金五五分仓

最直观的做法：两个策略各拿一半资金独立运行，最后把两条净值曲线相加。

# 各拿一半初始资金
mr_cash = INIT_CASH * 0.5   # 均值回归资金
tf_cash = INIT_CASH * 0.5   # 趋势跟踪资金
# 各自独立回测，最后把两条净值曲线简单相加

结果很尴尬：最大回撤只是略微改善（31.27% 对 33%~34%），CAGR 几乎正好卡在两者中间，而索提诺比率反而比单独跑任何一个都更差（0.623 对 0.858 和 0.908）。

为什么？ 因为固定五五分仓，不能让一个策略的「闲置时间」为另一个策略工作。当均值回归有 70% 的时间空仓时，那一半资金就干躺着，不产生任何收益。

一句话：把两条净值曲线相加，根本不是真正的「组合策略」，只是把两条中度相关的收益流做了平均。这不是有意思的问题。

三、尝试二：让它们共享一个资金池

更有意思的版本，关键不在「资金权重」，而在「持仓时间」。既然均值回归进出快、趋势跟踪持仓久，那如果两者能从同一个资金池取钱，均值回归频繁的短线持仓就能不断释放现金给趋势跟踪用，反之亦然，而不是固定的一半资金永远闲置。

vectorbt 原生支持这种玩法，靠的是 cash_sharing=True 搭配 group_by=True：

pf_shared = vbt.Portfolio.from_signals(
    close=close_combined, open=open_combined,
    entries=entries_combined, exits=exits_combined,
    init_cash=INIT_CASH, fees=FEES, slippage=SLIPPAGE, freq="1d",
    direction="longonly",
    group_by=True,        # 把 MR 和 TF 当作同一个组合
    cash_sharing=True,    # 共享同一个资金池
    size=1.0, size_type="percent",  # 每次信号占用 100% 的可用现金
    call_seq="auto",      # 同一根 K 线上，先处理卖出再处理买入
)

四、隐藏在交易数里的陷阱

请回头看一个被忽略的指标——交易笔数：五五分仓版本有 720 笔交易，共享资金池版本却只有 377 笔。340 多笔交易凭空消失了。 这绝不是噪声。

原因在这里：当 size=1.0 时，每个信号会占用当前所有可用现金。趋势跟踪一持仓就是好几周（它单独运行时的市场暴露度高达 67.8%）。在它持仓的每一周里，均值回归的 RSI(2) 信号（大约每 10 个交易日触发一次）压根没有现金可用，直接被跳过。

这不是同一天的巧合，而是均值回归在整个趋势跟踪持仓期间被彻底锁死。

所以所谓的「改善」，根本不是两个策略并行互补，而更像一个优先级队列：谁先抢到现金，就把另一个堵在门外直到自己退出。多出来的收益，来自趋势跟踪偶尔的大赢家背后压了更多资金，代价是均值回归的大量交易根本没发生。

这是个真实的结果，但它回答的，不是我们最初想问的那个问题。

五、调低「激进度」：让两者真正并肩作战

要让两个策略真正同时运行，我们把 size 参数从 100% 往下扫：

# 扫描不同的仓位比例（占可用现金的百分比）
for size_pct in [1.00, 0.70, 0.50, 0.35]:
    pf = vbt.Portfolio.from_signals(
        # ... 其余参数同上 ...
        size=size_pct,        # 每次信号只占用一部分可用现金
        size_type="percent",

        group_by=True,

关键变化：只要 size 降到 0.70 或以下，交易数立刻弹回 720——两个策略的全部交易都回来了。因为每个信号现在只占用一部分资金，给另一个信号留出了同时入场的空间。

这才是真正在测试「错位的持仓时间能否让资金被高效复用」这个问题。 答案是：某种程度上可以——

  • • size=0.70 时夏普（0.769）同时跑赢两个单独策略、也跑赢五五分仓；
  • • 最大回撤压到 24.84%，明显低于任何一个单独策略；
  • • 代价是 CAGR 相对 size=1.0 版本有所下降——这是「不把资金集中押注单笔交易」的必然取舍。

这里没有一个「绝对正确」的设置：把 size 推向 1.0，你得到更高的绝对收益，但策略行为更像「顺序优先级」而非真正的组合；把它拉到 0.5~0.7，你得到一个两个信号真正共存的组合，风险调整后指标更好、回撤更浅，但要牺牲一部分 CAGR。

六、几个必须诚实说清的坑

在你把这套思路用到实盘之前，请务必记住下面几点：

1. 这个参数是「看着结果」挑出来的。 因为 size = 0.70 在这次、这段 26 年 SPY 数据上夏普最高就选它，这是一种轻微的样本内过拟合（in-sample optimization）。真正稳健的下一步，是验证 0.6~0.7 这个区间能否在样本外或换一个标的上依然成立。

2. 相关性从一开始就不乐观。 0.424 的日收益相关性，说明这两个策略远没有「盈亏形态相反」看起来那么解耦。改善风险调整指标的主要功臣，其实是资金效率（让闲置现金被复用），而不是两条收益流之间真正的对冲。

3. 这依然只是一个标的、一段 26 年的行情。 这段主要由长期牛市加三次急跌构成的样本，只是所有可能市场里的一次抽样。组合两个策略并不能修复样本量太小的问题——它只是又多引入了一个（同样在这段数据上拟合出来的）参数。

总结

这次实验最大的收获，不是「均值回归 + 趋势跟踪能不能赚钱」，而是一个更底层的认知：

「组合两个策略」听起来是一个动作，实际上它隐藏了一连串设计决策——固定分仓还是共享资金？在共享池里下多大的仓位？——这些决策对结果的影响，远远超过「组合」这件事本身。

给正在学 Python 量化的你几条实用建议：

  1. 1. 警惕「净值相加」式的伪组合：那只是收益平均，不是策略协同。
  2. 2. 关注交易笔数这种「元数据」：夏普变好了，但交易数腰斩，说明背后发生了你没预期的机制变化。
  3. 3. 区分「资金效率」和「真正的分散化」：很多看似漂亮的组合收益，其实来自资金被复用，而非收益之间的对冲。
  4. 4. 凡是「看着结果选出来」的参数，都要做样本外验证，否则回测再漂亮也可能只是过拟合。

最初那条评论的直觉没错：这两个策略确实有「可能互补」的形态。但它们是否真的能稳健地互补，仍是一个开放问题。而诚实的答案是：细节，比「组合」这个动作本身重要得多。
