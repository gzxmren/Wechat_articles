1 · 它不是聊天框

四个方向
创作 5 · 科研 3 · 办公 3 · 地基 6
再说清主角。DeepSeek Harness（命令行里叫 dsh）是 DeepSeek 开源的 Agent 运行框架，官方一句话定义就七个词：Model + Harness = Agent。模型是脑子，负责想；Harness 是手脚，负责读文件、跑命令、调工具、记住上下文。
同一句话，左边那个只能给你一段文字，你还得自己复制；右边那个读完表、写好文件，跟你说一句「存好了」。这就是「装插件」这件事的全部意义——不是让模型变聪明，是给它长出能碰东西的手。
9 月底桌面端 v0.2 预览版发布，最大的变化是插件管理页面上线了。以前装插件得敲命令行，现在在设置里输入包名就行，还能停用、卸载、看来源。macOS 和 Windows 都有开箱即用的安装包，已上线 DeepSeek 官网。
所以这 20 个东西真正的分类，不是「创作 / 科研 / 办公 / 变现」——那是作者的分法。真正的分类是「地基 / 干活 / 变现」：前者决定你能不能找到插件，中间决定你能干多少活，最后那三个才谈钱。

开口说话
dsh-mic-input

输入框左边多一个麦克风，说完直接落进输入框；录音时有电平、计时和边说边出的文字
这五个里，只有 dsh-mic-input 是每天都会伸手去点的。它不解决内容质量，解决的是「想法在嘴上、手在别处」这个错位——你最好的想法往往出现在通勤路上，而不是坐在电脑前。
分发和公众号那两个，省的是「一下午」这种一次性的苦工。一篇文章手动改成四个平台版本，改到第三个平台你就开始复制粘贴了。dsh-agent-teams 门槛最高，它是给同时运营几条内容线的人用的；只有一条线的人装了，反而是负担——多一个要管理的团队，而不是多一个替你干活的。
小说那条里作者写了一句很值得琢磨的话：正文不进写稿上下文，模型只从你的点赞点踩里总结偏好，越用越懂你。这是把「调文风」从提示词工程，换成了偏好积累。
3 · 别让它编文献
三个插件，治的是同一个病：不知道的时候，它照样给你一串参考文献
科研这一组只有三个，但解决的是最要命的问题。用过 AI 写文献综述的人都撞过同一面墙：它会编。期刊名像真的，卷号像真的，页码也像真的，一查全部不存在。

跑实验
dsh-autoresearch

给一个研究目标、设定轮次，它连续改、测量、保留或回滚，结果直接显示在会话顶部；开工前先建本地保护，能用 Git 就存基线，否则打私有快照，翻车自动恢复受保护文件
写论文
dsh-plugin-academic-paper

从 arXiv 和 Semantic Scholar 真实数据源检索，出 GB/T 7714、APA、BibTeX 引用，能建本地文献库批量导出
查资料
dsh-deep-research

基于官方 workflow 引擎、按控制论和信息论设计，流程跟着研究进展自己调，不是固定的提示词流水线
第三个最好懂，第一个最激进，第二个最值得抄。
dsh-plugin-academic-paper 的做法，可以搬到任何一个场景：它没有教模型「不要编」，而是把「查」这件事从模型手里拿走了。插件负责去真实数据源检索、负责生成引用格式，模型只负责解读和综述。两件事一人一半，编造这条路从结构上就断了——不是靠自觉，是靠分工。
凡是「模型做不到」的问题，先想一遍：是不是这件事根本不该交给模型。让它算数、让它查库、让它记事实，都不如让它读别人算好查好记好的结果。

白话开发
dsh-dev-mode

几句大白话讲需求，它走完开工体检 → 写计划 → 独立评审 → 后台实现与自测 → 独立测试 → 修复 → 复测 → 交付；你说不清要什么时，它先给三个具体示例让你选，全程最多问一轮

dsh-browser

直接开真的 Edge 逛网页、点按钮、填表单、截图；不用配 CDP，不用跑 MCP。登录态和 Cookie 在会话内保留
操作桌面
dsh-computer-use

截图 + UIA + 鼠标键盘操控，原生组件随包提供，让它看得见也点得动。目前只有 Windows 版
这三个的共同点是：它们交出来的不是一段字，是你机器上的状态变化。一个文件被改了、一个订单被提交了、一个表单被填了。所以权限这件事必须提前想清楚，别等它动完才反应过来。
坑以为装了 dsh-browser 就永久登录了
改登录态和 Cookie 只在会话内保留，关掉重来要重新登；别把它当免密通道用
坑让 dsh-dev-mode 在随便哪个目录开工
改给它一个空目录或单独的项目目录。它会在里面改文件、跑命令，位置越干净越安全
能力排序和价值排序是反的：越能自己动手的插件，越需要你守在旁边。装 dsh-computer-use 之前先想清楚——你愿意让它替你在桌面上点多少下。
5 · 三条变现路
这三条不是插件，是生意；夹在清单中间，读的时候最容易滑过去
作者把它们混在 20 个里，编号 12 到 14。读清单的时候这三条最容易被当成「凑数的过渡段」滑过去，但对真想做点什么的人来说，这三条比前面 17 个插件都值钱。
路径它到底是什么
企业底座
Harness 是 MIT 协议开源，能任意二次开发、闭源商用、私有化部署；不绑 DeepSeek 模型，OpenAI、Anthropic 都能接，企业内部的模型网关也能通过自定义接口加进来
卖结果
付费模式正在从「算力消耗付费」转向「结果交付付费」：客户不为抽象的模型算力买单，而是为「修复一个代码漏洞」「完成一个功能开发」这种具体结果付钱
做插件
官方按模型 API 用户口径统计，约 60% 的 Harness 用户用了第三方插件；对开发者来说，插件开发本身就是一条变现方向
把三条摆在一起看，门槛差得很远。
前两条要的是客户关系和交付能力，不是技术。个人今天能动手的只有第三条。但第三条也别高兴太早：GitHub 上的 dsh-plugin 话题是开放的，谁都能贴标签，抢注一个长得像的包名就是一次投毒机会——这正是第 6 节里 dsh-topic-audit 存在的理由。
另外说句实在话：这三条里唯一能验证「你有没有真本事」的是第二条。卖结果意味着你得敢对交付负责，而不是把 API 调用次数卖给别人。这也是我判断一个 AI 服务商靠谱不靠谱的第一个问题：你按什么收钱？

这六个里我只推荐前两个必装：dsh-market 解决「找得到」，dsh-web-ui 解决「重复的活能自动跑」。侧栏和手册是舒适度问题，dsh-find-plugin 要等生态大到搜不动了才有价值。
最后一个值得单独说一句。一个社区需要专门的工具去「挑假货」，说明这个生态已经大到有投毒价值了。装任何插件之前，先看仓库是不是原作者、star 和 issue 是不是活的、最近一次提交是什么时候。名字像、图标像，都不算证据。
插件生态的风险从来不在插件本身，在你「看到一个名字就装」的那个动作上。
7 · 装机两条路
桌面版点两下，非桌面版敲一行命令；两套插件目录各管各的
装法分两条路，取决于你用桌面版还是 Web 端。
桌面版：macOS / Windows
去 DeepSeek 官网下 v0.2 预览版安装包，开箱即用，不用装 Node。装完进 设置 → 插件 → 添加插件，粘包名就行。
# 桌面版：官网下 v0.2 预览版，装完在 # 设置 → 插件 → 添加插件，粘下面这串 github:lingyingaojue/dsh-dev-mode
非桌面版：Web / Linux / Termux
先确保 Node.js 18+ 和 dsh CLI 都在 PATH 里，然后一条命令。
# 非桌面版先装 Node 18+ dsh plugin --profile web add \   dshmarket
安卓手机可以在 Termux 里跑一键部署脚本，起来后浏览器开 127.0.0.1:3080 填 API Key 就能用；Linux 服务器直接 npx @deepseek-ai/dsh web 启动。
坑以为 Web 端装过一遍，桌面版里也就有了
改Web CLI 只管 web profile，两套插件目录是分开的，得各装一次
坑照着教程去 clone 仓库、本地构建
改普通用户不需要。桌面版在「添加插件」里粘包名就装完了，clone 是开发者的路子
这个周末，就做这三件
1  装 dsh-market，先把插件市场跑起来
2  挑一件你每周都要重复的活，在 dsh-find-plugin 里描述它
3  装上对应的那个插件，完整跑一遍，记下卡在第几步
8 · 别一次装满
作者最后那句「别一上来就想装 20 个」，是整篇最值钱的一句
原因不只是「用不过来」。每个插件都会往系统提示里塞自己的指令和工具描述，装到十几个以后，模型每天要先读完一堆它此刻根本用不上的规则，才轮到你说话。插件之间有隐性的注意力竞争，这件事在插件市场页面上看不出来。
更根本的一层：装插件的技术门槛已经降到接近零了，桌面版点两下就完。真正难的是想清楚——我到底在哪些事情上反复浪费了时间。
先装 dsh-market 和 dsh-web-ui，再从前 15 个里挑三个跟你当前工作最相关的，一个周末一小时。剩下十几个，等你真的卡住了再去装——那时候你才知道自己要什么。
最后留一个可以带走的思路：不要问「这个插件能干什么」，要问「我上周重复做了三遍以上的事是什么」。前者会让你装 20 个，后者会让你装 3 个，而且真的省下时间。
你每周花时间最多的重复性工作是哪一件？
在评论区说说具体是哪件事、一周大概占多少时间，我帮你想想有没有现成的 Harness 方案，或者该往哪个方向找插件。
