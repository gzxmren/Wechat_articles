用了两年 Markdown，Claude Code 团队的人开始转向 HTML 了

从0到AI，每天为你拆解硅谷最前沿的 AI 创业实战与商业洞察。

前天，Claude Code 团队成员 Thariq 发了一篇文章。

标题是《Using Claude Code: The Unreasonable Effectiveness of HTML》。

两天内，780 万人看过，超 2 万人收藏。

它爆火的原因，是因为说了一个反常识的事：

AI 的最佳输出格式，可能不是 Markdown，而是 HTML。

先说为什么大家默认选 Markdown

Markdown 好用是真的。

简单、轻量、方便编辑，放进代码仓库也没压力。

AI 和人沟通，Markdown 几乎成了默认语言。

写计划，用 Markdown。写总结，用 Markdown。写 PR 说明，还是 Markdown。

这很合理。过去我们担心 AI 写不出来，Markdown 够用了。

现在的问题变了

现在 AI 写得太多了。

一份实现计划，可以写几百行。一个技术报告，可以把背景、方案、数据、结论全都整理好。

问题是：人真的会读吗？

Thariq 说了一个很真实的场景：

Claude 生成了一份看起来很完整的 Markdown，你打开扫一眼，觉得大概没问题，就让它继续了。

不是因为内容不好。而是太长、太平、太像一堵文字墙。

Markdown 是线性的。

标题下面是段落，段落下面是列表，列表下面是代码块。

短的时候很清楚，一长就很考验耐心。

所以核心问题不再是"AI 能不能生成文档"。

而是 AI 生成了这么多之后，人还愿不愿意读、能不能快速判断。

HTML 能做到 Markdown 做不到的事

Thariq 说的 HTML，不是让你去做网站。

而是让 Claude 把复杂内容组织成一个更容易进入的页面。

同样是实现计划：

Markdown 版：一段接一段，从头读到尾。

HTML 版：不同方案放进 tab，关键流程画成图，代码片段放旁边，结论放前面，细节可以折叠。

你不再是在"读完一份文档"，而是在浏览一个已经被整理好的工作台。

布局、图示、视觉层级——这些 Markdown 很难做到，HTML 天然就能支持。

Thariq 提到一个细节：没有 HTML 时，Claude 有时会用 ASCII 字符在 Markdown 里"假装画图"，甚至用 Unicode 字符模拟颜色。

这很有趣。也说明 Markdown 本身不太适合复杂的视觉表达。

更关键的：HTML 可以变成小工具

这才是文章真正让人眼前一亮的地方。

Claude Code 生成的 HTML，不只是给你"看"的，还可以让你"用"。

举个例子：

你要排 30 个 Linear tickets 的优先级。

如果在聊天框里做，会很别扭——一条条说，这个往前，那个往后。

换一种方式：让 Claude 生成一个 HTML 看板。

页面里有 Now、Next、Later、Cut 四列，每个 ticket 是可以拖动的卡片。Claude 先排一版，你拖拽调整，最后一键导出 Markdown。

再比如调 system prompt：

Claude 生成一个 HTML 页面，左边是可编辑的 prompt，右边是实时预览，底部是 token 计数和复制按钮。

改几个字，右边立刻更新。不用来回粘贴，不用切换窗口。

HTML 把 Claude 的输出从"等你阅读的文档"，变成了"可以操作的界面"。

人做判断时，往往不是线性阅读，而是在比较、移动、筛选、调整。

HTML 把这部分动作接住了。

但 HTML 不是没有代价的

Thariq 说得很直接：HTML 通常比 Markdown 慢 2 到 4 倍，token 消耗也更多。

版本控制也是问题。Markdown 的 diff 很清楚，HTML diff 往往很吵。

所以他的建议是：

Markdown 适合轻量文本、README、简单说明、长期维护的文档。

HTML 适合复杂计划、方案比较、可视化报告、交互调试、一次性决策界面。

这不是格式之争，是场景选择。

最后一个点，也是最重要的

Thariq 在文章结尾提到一个感受，我觉得是整篇文章真正的核心：

他喜欢 HTML，不只因为它表达力更强，而是因为它让自己更 stay in the loop。

Claude Code 生成一份几百行的 Markdown 计划，你扫一眼觉得差不多，就让它继续。

表面上看，AI 更自动化了。

但实际上，人可能也更容易失去判断感。

HTML 带来的变化，是把人重新拉回来。

计划更容易读，方案更容易比较，代码变化更容易审查，结果更容易回传给 Claude。

HTML 的价值，不是让 Claude 更独立，而是让人更容易介入。

这可能就是 Thariq 说 HTML "unreasonably effective"的原因：

看起来只是换了个格式，但真正改变的是人和 Claude Code 协作的感觉。
