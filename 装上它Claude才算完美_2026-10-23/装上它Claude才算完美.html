装上它Claude才算完美

 

为自己代言个小程序

现在许多团队都给 Claude 加载了各种工具，比如日历、CRM、数据仓库、客服系统等等，功能越多，存在的问题就越突出——模型可以很轻松地调用工具，但是未必知道这个岗位该先看什么，哪些环节不可以省略，哪些操作需要别人确认。

Anthropic 开源的 knowledge-work-plugins，把岗位上积累的经验转化为 Claude 可以调用的工作流程。

这些插件面向 Claude Cowork，也兼容 Claude Code，仓库中包含了生产力、销售、客户服务、产品管理、市场营销、法律工作、财务管理、数据分析、企业搜索以及生物研究等方面的插件。

插件结构中的 skills/ 存放领域知识和分步说明，commands/ 提供显式斜杠命令，.mcp.json 配置外部工具连接，.claude-plugin/plugin.json 是插件清单。这些内容以 Markdown 和 JSON 为主，不需要构建步骤。

该插件最重要的作用就是把“模型是否能回答问题”提升为“模型能否按照团队的标准来做事情”。

以销售插件为例，36 项技能涵盖了通话准备、通话总结、客户研究、商机审查、管道复盘、预测以及续约风险等工作。

加上与 CRM、邮箱、日历、会议记录和团队聊天的联动之后，技能就可以读取真实的上下文了；如果没有这些联动的话，则可以处理管道导出、会议纪要或者联系人列表这样的文件。

官方给出的例子是 /sales:call-summary 会自动生成跟进邮件草稿、团队汇总以及提出的 CRM 更新建议，但是并不会在没有得到用户的同意之下就把这些信息写进 CRM 或发出邮件。

本套方案还有一个重要的边界条件，即电子邮件、聊天、会议转录和文档中的外部内容只被当作信息，不会自动变成指令。

在更新记录、发送邮件、发送信息或者安排会议的时候，实际能力由连接器权限决定；如果写入工具被禁止的话，读取仍可继续，受阻的更改会转为手工待办事项。

对使用者而言，这比单纯的添加一个“自动化”的按钮要重要得多：流程已经被编好了，但最终控制权仍然可以留在权限和审批上。

安装的方法很简单，在 Claude Code 中，先添加插件市场，再安装指定插件：

claude plugin marketplace add anthropics/knowledge-work-plugins
claude plugin install sales@knowledge-work-plugins

安装之后，技能会在请求匹配时被自动激活，斜杠命令也能够直接使用。

管理员可以按连接器的工具粒度设置允许、询问或阻止，而团队可以修改技能文档、更换连接器、添加公司的专有名词和内部工作程序。

另外一方面也可以理解为：企业的知识不需要全部变成一个大而全的平台才有可能进入到人工智能的工作流中去，一份简单的 Markdown 文档就代表了可以审核、修改、提交 Pull Request 的工作流程资产。

它不会自动解决权限配置、数据质量以及组织协同的问题，但是给了我们一个明确的方向，即把各个岗位的方法记录下来，在限定范围内由模型去操作。
