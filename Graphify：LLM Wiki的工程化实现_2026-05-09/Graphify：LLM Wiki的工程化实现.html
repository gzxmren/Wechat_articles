Graphify：LLM Wiki的工程化实现

一句话定位：将代码、文档、论文、图片甚至视频自动转化为可查询知识图谱的开源 AI 编码助手 Skill，一次编译、多次查询，Token 消耗降至传统方式的 1.4%。

一、它是什么？解决什么问题？

当 AI 编码助手（Claude Code、Codex 等）处理大型项目时，核心痛点是"上下文窗口装不下"。每次提问都要重新读取文件，Token 账单居高不下，而且跨文件的依赖关系、设计决策的"为什么"往往丢失。

Graphify 由伦敦 AI 研究员 Safi Shamsi 开发，将 Karpathy 提出的"LLM Wiki"知识编译理念工程化为完整工具链。输入/graphify .命令，它自动扫描整个项目文件夹——代码、Markdown、PDF、图片、视频——通过 Tree-sitter 本地 AST 解析 + LLM 语义抽取，生成一张可交互的知识图谱。后续查询直接走图谱，不再重复读取原始文件。

核心优势：71.5 倍 Token 节省（Karpathy 52 文件语料测试：查询成本从 123k tokens 降至 1.7k tokens），且无需部署向量数据库。

三、它是如何做到的？

Graphify 采用多阶段流水线架构，每个阶段独立模块化：

detect（文件收集）→ extract（AST + LLM 节点/边提取）→ build（NetworkX 图构建）→ cluster（Leiden 社区检测）→ analyze（God Nodes + Surprises）→ report → export

关键技术决策：

  • 代码解析零 Token：Tree-sitter 在本地生成 AST、调用图和文档字符串，不发任何数据到云端
  • 图聚类替代向量检索：Leiden 算法基于图拓扑结构做社区发现，天然支持多跳推理，比向量相似度的单步检索更适合理解"关系"
  • 不自带 LLM：复用编码助手已配置的 API Key，只发送语义描述，永远不发送原始源代码
  • 安全设计：输入验证、路径包含检查、HTML 转义、防御 SSRF/Cypher 注入/XSS，零遥测

五、为什么值得关注？

  1. Token 效率本质级提升：71.5 倍节省不是微优化，是架构级变革——从"每次全量读取"变为"一次编译、增量查询"，对企业级 LLM 采购成本有直接影响
  2. 无需向量数据库：Leiden 图聚类替代 Embedding + 向量检索，部署复杂度和基础设施成本大幅降低，对私有化部署场景友好
  3. 知识溯源透明：EXTRACTED vs INFERRED 的区分源自作者医疗知识图谱研究背景（MICAD 2025），对合规审计场景有实际价值
  4. 生态适配广：18+ 编码助手开箱即用，团队协作支持 Git hook 自动重建和 merge driver，工程化程度高
