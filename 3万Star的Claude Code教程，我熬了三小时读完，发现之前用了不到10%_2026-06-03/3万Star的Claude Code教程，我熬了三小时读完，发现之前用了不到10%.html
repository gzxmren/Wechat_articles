3万Star的Claude Code教程，我熬了三小时读完，发现之前用了不到10%

wuhiufan

我自认为用Claude Code挺熟练的。敲claude进对话，问它写代码，复制粘贴到编辑器，跑一下看效果。觉得这就是AI编程的全部了。

直到我花三小时读完了一个GitHub项目——32.9K Star，叫claude-howto。读完之后，我只剩一个想法：我之前用Claude Code的方式，大概只用了它10%的能力。

斜杠命令、记忆系统、Skills、子代理、Hooks、MCP、插件——这些词我都见过，但从没想过它们拼在一起是一整套自动化工作流引擎。就像你买了一台MacBook Pro，结果只用了它上网看视频。

今天把我的读书笔记分享出来，希望帮你少走弯路。

这个项目到底是什么

项目地址：https://github.com/luongnv89/claude-howto

一句话概括：目前最完整的Claude Code学习指南，没有之一。

它做了两件别的地方没做到的事：

第一，把每个功能从"解决什么问题→怎么配→怎么用在真实项目"这条线讲清楚了，不是甩个功能列表就完事。每个模块都带可直接复制的模板。

第二，设计了一条学习路径——10个模块，从入门到高级依次递进，每个模块标了预估学习时间和学完能干什么。

下面我逐个拆。

模块一：斜杠命令——把重复操作变成一句话

输入/xxx回车，自动跑一整套工作流。不是简单触发一段提示词，是可以包含多步操作、文件生成、Git操作、API调用的完整任务流。

Claude Code官方内置了60+个斜杠命令，这个项目额外提供了一批可直接复制到项目里的模板：

命令 干什么 什么时候用
/optimize 分析性能瓶颈，给优化建议和代码 写完代码跑一遍，找出O(n²)
/review 自动代码审查，输出结构化报告 提PR前自动检查安全问题
/commit 生成规范的commit message 团队统一格式
/pr /push-all /setup-ci-cd 创建PR/一键推送/生成CI/CD配置 日常提交、新项目初始化
/doc-refactor /unit-test-expand 重构代码同步更新文档/补单元测试 大规模重构、TDD补覆盖率

学完能做什么：把团队里反复做的开发操作变成一句话命令，不用再各自为政，敲斜杠统一标准。

模块二：记忆系统——别让AI每次从零开始

Claude Code能记住项目背景、团队规范、技术债务。不用每次对话都重复"我们项目用的是XXX框架"。

三种记忆类型：

项目记忆（CLAUDE.md）：放项目根目录，Claude Code每次启动自动读取。项目背景、团队规范、技术栈约束、anti-patterns全写进去。

个人记忆（~/.claude/CLAUDE.md）：记录你个人的偏好、常用工具、工作风格，跨项目都生效。

目录API记忆：通过代码接口让AI在读写文件时自动访问目录结构，保持对项目结构的实时理解。

学完能做什么：你的AI不再是"每次对话从零开始的失忆症患者"。上下文理解能力上去了，编程效率才能质变。

模块三：检查点——对话的版本控制

保存对话状态到文件，随时回退到任何一个历史节点继续工作。类似Git的commit，但作用于对话。

学完能做什么：实验性开发时特别好用。想试个激进方案？先打检查点再去试。成了继续，败了回退。不再有"做到一半发现方向错了只能从头来"的绝望感。

模块四：Skills——一键召唤专家

Skill是可复用的Agent技能包，比斜杠命令更重——不是一个操作，是一整套工作流。Claude Code执行任务时会自动调用对应的Skill。

项目提供的现成Skill：

Skill 用途
code-review bug-hunt test-engineer 代码审查/Bug定位修复/测试生成
doc-generator doc-writer refactor API文档生成/技术文档写作/代码重构含气味分析
brand-voice 按品牌风格生成文案

学完能做什么：把Claude Code打造成多专家协作团队。代码审查用它、写文档用它、生成测试用它。不用每次从头写提示词，调用Skill就行。

模块五：Hooks——自动化触发器

Hooks在Claude Code执行过程中自动触发脚本。可以配在提交前、工具执行前、会话结束时、消息发送后。支持command/http/prompt/mcp_tool/agent等触发类型。

几个实用的Hook示例：

Hook 触发时机 干什么
pre-commit.sh 提交前 自动检查代码格式、安全问题
security-scan.sh 工具执行前 扫描敏感信息泄露
context-tracker.py 会话中 追踪Token用量避免上下文溢出
log-bash.sh 工具执行后 记录所有Bash操作日志
notify-team.sh 会话结束 自动发会话总结到Slack

学完能做什么：搭真正自动化的CI/CD流程。Claude Code跑操作时自动过安全检查、格式化检查、通知团队——不是需要你盯着的工具，是自己跑的系统。

模块六：MCP——让AI直接操作外部工具

MCP（Model Context Protocol）是Claude Code连接外部工具和API的标准协议。接上之后，GitHub、数据库、飞书、Slack、各种外部服务——Claude Code都能当原生工具用，不是通过API调用那种。

项目详细讲了MCP服务器的配置（stdio/HTTP两种方式）、认证方式（API Key/OAuth/Bearer Token）、资源访问权限控制，以及怎么自己写一个MCP服务器。

我的判断：MCP让AI编程从"在代码里用AI"升级成"用AI操作整个开发环境"。这是最值得深入的方向之一。

模块七：子代理——多AI同时干活

Claude Code可以同时跑多个专用AI助手，每个有独立的上下文、专业方向和任务执行能力。主代理协调，子代理干活。

项目提供的子代理模板：code-reviewer、debugger、test-engineer、documentation-writer、data-scientist、secure-reviewer、performance-optimizer、implementation-agent。每个用YAML配置专属系统提示词、工具集、权限级别和模型选择。

我的判断：子代理玩透了，AI编程能力会上一个层次。这是天花板之一。

模块八：高级功能——把Claude Code变成自动化系统

  • 规划模式：复杂任务AI先出计划，你批准后再执行
  • Auto Mode：后台安全分类器在每次操作前审查，敏感操作有保护
  • 后台任务：长时间任务放后台跑，不阻塞当前对话
  • 权限模式：从每次确认到完全放权，按需配
  • Print Mode / TUI Mode：非交互模式用于CI/CD，全屏TUI适合本地开发

模块九：插件系统——把团队能力打包分发

把多个Skills、Hooks、子代理、MCP配置打包成一个可分发的插件，团队成员装了就有完整功能套件。项目给了三个完整插件示例：

  • pr-review：PR审查插件，3个子代理+3个命令
  • devops-automation：DevOps自动化插件，3个子代理+4个命令
  • documentation：文档生成插件，3个子代理+4个命令

学完能做什么：把团队最佳实践封装成插件。新人装了插件就等于拥有了整个团队的工程能力。不是培训，是工具赋能。

模块十：CLI和脚本化——无人值守自动化

Claude Code的命令行接口，支持管道、脚本化、CI/CD集成。claude -p非交互模式接收文件输入、环境变量配API密钥和默认模型、配合GitHub Actions使用。

学完能做什么：把Claude Code集成进自动化流水线。真正的AI编程自动化，不需要人盯着。

为什么你真的应该花时间学

三个理由：

1. 这是最完整的Claude Code教程，没有之一。 10个模块覆盖全部核心能力，每个带可直接复制的模板。官方文档都没做到这个程度。

2. 它展示了AI编程工具的正确用法。 大多数人用Claude Code就是"问问题→给答案"。这个项目告诉你：正确用法是搭成一套可编程自动化系统。

3. 它的设计本身就是教学产品。 不是功能手册的写法，是学习路径的写法。学完一个自然知道下一个该学什么。

怎么获取

GitHub直接访问：https://github.com/luongnv89/claude-howto

英文版在根目录，中文翻译版在zh/子目录。想用模板的话，直接去对应模块文件夹，把.md文件复制到你的项目里，按README说明配置就行。

最后

AI编程工具在快速进化，但大多数人的用法远远没到天花板。不是工具不够强，是你不知道它能做什么。

这个项目帮我把Claude Code的能力边界看清楚了。我现在的用法已经从"问问题"升级成"搭系统"——记忆让AI理解项目上下文，Skills负责专业任务，Hooks做自动化检查，子代理并行处理复杂任务，MCP连接外部工具形成完整生态。

建议你认真动手去配、去用，别浅读。你可能会发现：之前以为自己会用Claude Code，其实只用了它10%的能力。
