✍️ 小以AI · 第一观察者

💡 第12期我们拆了 audit-xls——教 AI 怎么"审"模型：公式追溯、硬码检测、平衡校验。但它审的是"已经存在的活的工作簿"。模型从哪来？脏数据怎么进？这是另外两个 Skill：xlsx-author 负责"生成"——在无头环境里直接产出一个 .xlsx 文件（不是去驱动你打开的 Excel）；clean-data-xls 负责"清洗"——把乱七八糟的表先收拾干净再分析。三者拼成"生成 → 清洗 → 审计"的 Excel 三件套：一个管"造出来"、一个管"洗干净"、一个管"查得对"。Anthropic 把 Excel 这条价值链也拆成三段，各自工程化。拆完你会发现，Excel 最稳的落点依然是"可审计"——蓝黑绿三色约定、Checks 页签、helper column 透明可溯，AI 把生成与清洗做对，人只定 policy。国内建模 / 估值 / 数据岗，恰恰天天在"活的工作簿驱动不了、文件交付靠手动导出、蓝黑绿不统一、Checks 缺失、脏数据漏检"上耗时间。


01 / Excel 生成与清洗：从"能算出"到"能交付"

① Skill深度拆解：Anthropic原版在做什么

A. xlsx-author —— Excel 文件生成（无头托管 / 托管智能体模式）
触发场景："produce / generate / build an xlsx"、"export to Excel"、"deliver as a file"——典型是"无头托管"（不打开 Office 应用、由 AI 托管运行）模式下没有现成 Excel 可操作时，需要把工作簿当作"文件产物"直接生成交付，而不是通过 mcp__office__excel_* 去驱动一个活的工作簿。
输出契约：写入 ./out/<name>.xlsx（目录不存在则建 ./out/）；最终消息返回相对路径，供编排层收集。
怎么造：写一段短 Python + openpyxl——B2="Revenue" 蓝字（硬编码输入）、DCF!C5="=Inputs!C2*(1+Inputs!C3)" 黑字（公式）、跨表链接绿字。
约定（镜像 audit-xls）：蓝 = 硬编码输入、黑 = 公式、绿 = 跨表 / 文件链接；计算格零硬码，每个输入落在 Inputs 页；命名区域供 deck / memo 引用；Checks 页签做平衡校验（资产负债表平衡、现金流量勾稽等）显 TRUE / FALSE；一个模型一个文件，除非显式要求否则不追加。
何时不用：若 mcp__office__excel_* 可用（Cowork 插件模式），用那些——它们能驱动你活的工作簿并带复核 checkpoint。本 Skill 是无 Office 时的"文件产出兜底"。

B. clean-data-xls —— 脏数据清洗（活动工作表 / 独立 .xlsx）
触发场景："清理这批数据"、"标准化"、"修正格式"、"去重"、"把这一列规范化"、"这数据太乱了"等中文指令。
环境分支：在 Excel 内（Office Add-in / Office JS）→ 用 Office JS（range.values 读、range.formulas 写 helper 列）；操作独立 .xlsx 文件 → 用 Python / openpyxl。
工作流六步：
· ① 界定范围：指定区域（如 A1:F200）就用指定区域，否则用整表的"已用区域"；逐列分析主导类型（文本 / 数字 / 日期）并标出异常。
· ② 检测问题：9 类——空白符、大小写不一（usa / USA / Usa）、数字存为文本（夹杂 $ / , / %）、日期混格式（3/8/26 / 2026-03-08 / March 8 2026）、重复（精确重复 + 近似重复）、空值、混合类型（98% 数字却混 3 个文本）、编码乱码（mojibake Ã© / â€™）、错误值（#REF! #N/A #VALUE! #DIV/0!）。
· ③ 提议修复：改前先给汇总表（列 / 问题 / 数量 / 建议修法）。
· ④ 应用修复：优先公式而非硬算值——能写成公式的就写相邻 helper 列（如 =TRIM(A2)、=VALUE(SUBSTITUTE(B2,"$",""))、=UPPER(C2)、=DATEVALUE(D2)），保持透明可溯；仅当用户显式要求或无公式等价时才原地覆盖。
· ⑤ 逐类确认：按空白符 → 大小写 → 数字 → 日期 → 去重的顺序，每类改完先给样本样例，再进下一类。
· ⑥ 报告：变更前后汇总。
关键纪律：透明优先于"干净"——helper column 让变换可追溯；破坏性操作（删重 / 填空 / 覆盖）必须用户确认；每类修完展示样本。

② 对应业务流程：国内券商 / 基金 / 企业财务，怎么做 Excel 生成与清洗

当前工作流（以建模 / 估值、数据 / 中后台、分析师为例）：
· 生成：模型 / 报告在 Excel 手搭 → 蓝黑绿靠人记 → Checks 页签基本没有（靠人工看资产负债表平衡）→ 导出交付。耗时：搭模型 1–3 天；对账 / 平衡 0.5 天（最痛）；交付 0.5 天。
· 清洗：从 Wind / 恒生 / 业务系统导出的表 → 手工 TRIM / 分列 / 改格式 / 去重 → 进模型。耗时：定位脏数据 0.5–1 天；清洗 0.5–1 天（易漏）；复核 0.5 天。

痛点清单：
· 生成：无头托管模式下没有活的工作簿可驱动；文件交付靠人手动导出；蓝黑绿不统一（公式里混硬码）；Checks 缺失导致交付后才发现资产负债表不平。
· 清洗：数字存文本、日期混格式、mojibake 乱码、#REF 蔓延；helper column 不会用，直接覆盖原值丢了溯源；去重不确认误删；GBK / UTF-8 编码打架。

谁在做这件事：建模 / 估值岗（生成）、数据 / 中后台（清洗）、分析师（两者都沾）——典型的"高计算、中判断"活（判断在模型结构与业务口径，生成与清洗是苦力）。

③ AI助力效果：自动生成 + 清洗，把"3–5 天"压到"半天~1 天"

可以替代的环节（AI做，人审核）：
· 生成：openpyxl 脚本 + 蓝黑绿 + Checks 自动出。时间：1–3 天 → 30 分钟；资产负债表 / 现金流量表平衡自动校验。
· 清洗：9 类检测 + helper column 自动。时间：1–2 天 → 20 分钟；变换全留痕可溯。

可以增强的环节（人+AI协作）：
· 批量多 sheet 模型生成：一次造含 Inputs / Calc / Checks 的多页签模型。
· 清洗 pipeline 化：一次跑全库导出的九类检测，输出 before / after 报告。
· Checks 自动平衡：生成即带平衡校验，交付前先 self-check。

不能替代的环节（人必须做）：模型结构 / 假设定夺、业务口径、最终签发与合规。

综合量化对比：传统 Excel 生成 + 清洗需 3–5 天；AI 辅助后 半天~1 天（含人审），效率提升约 60–75%，且资产负债表不平 / 脏数据漏检等错误率大降（以上为典型工作流耗时估算，非实测基准）。

④ 国内落地差异：工具 + 数据源 + 术语 + 监管，四道关卡

差异一：工具与习惯
· 海外用 openpyxl 直接生成 / Office JS 直接驱动；国内多用万得 / 恒生导出 + 人工 Excel——但只要走"无头托管"（不打开 Office 应用）这条路，国内 AI 同样没有"活着的"工作簿可驱动，只能把 Excel 当文件产物用 openpyxl 生成。
· 改造要点：用 openpyxl 兜底生成；Office JS 适配 WPS / 国产插件；导出环节固化快照防断链。

差异二：数据源
· 海外干净 feed；国内 Wind / 恒生 / 业务库导出字段乱、GBK 编码乱码、日期中文格式（"2026年3月8日"）。
· 改造要点：encoding 检测（GBK / UTF-8）、日期标准化（中文 → ISO）、数字去文本（¥ / , / %）。

差异三：术语与基准
· 海外蓝黑绿三色约定通用；国内"Checks 页签 / 命名区域"概念弱，模型多单 sheet 堆叠、硬码散落。
· 改造要点：引入三色 + Checks 页签 + 命名区域纪律，生成即审计就绪。

差异四：监管与合规
· 国内财报 / 尽调 / 估值底稿要求留痕可追溯；清洗的 helper column 恰好满足"变换可溯"。
· 改造要点：清洗留痕（原值 vs 新值对照）、生成 Checks 可复核，满足可追溯合规。

⑤ 国内对应工具现状：能"算"多，能"干净交付"少

生成：恒生 / 赢时胜 / 万得能出表，但多为"导出"非"工程化模型"；蓝黑绿 / Checks 基本无，交付后才对账。

清洗：Excel / Power Query / Python 都能洗，但 AI 化的"检测 → 提议 → 确认 → 溯源"闭环少；多为人工写公式、直接覆盖原值。

总结：国内 Excel 链仍偏"手搭 + 手洗"，缺"无头生成 + 三色约定 + Checks + 清洗溯源"。两个 Skill 国内改造的价值，是把"生成 → 清洗 → 审计"串成一条可交付、可追溯的 Excel 链——尤其帮国内建模 / 估值 / 数据岗避开"活的工作簿驱动不了、蓝黑绿不统一、Checks 缺失、脏数据漏检"的坑。

⑥ 优化方向与目标：这两个 Skill 国内改造的路线图（Dao-financial-services）

近期目标：openpyxl 生成 + 蓝黑绿 + Checks；clean-data 九类检测 + helper column
· 万得 / 同花顺拉数据 → openpyxl 生成含 Inputs / Calc / Checks 的模型；clean-data 跑九类检测 + helper column 留痕。
· 量化目标：Excel 生成 + 清洗从 3–5 天压到半天~1 天；资产负债表不平 / 脏数据漏检趋零。

中期目标：批量多 sheet 生成 + 清洗 pipeline + 与 audit-xls 联动
· 一次造多页签模型；清洗 pipeline 化跑全库导出；生成即带 Checks，清洗即出审计就绪数据，直接喂给第12期的 audit-xls。

远期目标：端到端（数据进 → 模型出 → 报告出 → 合规签发，人只定 policy）
· 终极状态：拿到原始导出，系统自动出"干净数据 + 蓝黑绿模型 + Checks 平衡 + 审计报告"，建模 / 估值岗只定结构与假设。

🎯 小以观察

观察一：三个 Skill 拼成"生成 → 清洗 → 审计"的 Excel 链——xlsx-author 管"造出来"、clean-data-xls 管"洗干净"、audit-xls 管"查得对"
三者底层同源：都是把"可信交付"工程化。这印证 Anthropic 的打法——把"Excel 价值链"按生成、清洗、审计三段拆开，每段一个 Skill，各自工程化。拼起来就是一条完整的 Excel 工作链，且从生成那一刻起就埋好审计钩子。

观察二：蓝黑绿三色 + Checks 页签是"可审计 Excel"的命根——和 audit-xls"可审计"、固收"聚合可溯"、估值复核"untrusted"同源
生成时就约定蓝（输入）黑（公式）绿（链接）、就放 Checks 页签做平衡校验，比事后拿 audit-xls 去救一个满地硬码的模型省力十倍。可审计不是审出来的，是生成时就设计出来的。

观察三：清洗的"helper column 优先于硬覆盖"是 AI 比人稳的落点——透明可溯、破坏性操作先确认
这恰是金融数据"可追溯合规"的硬要求。国内缺的不是清洗能力（Power Query / Python 都会），是"清洗留痕"的纪律——原值 vs 新值对照、变换可回放。clean-data-xls 把这条纪律工程化了。

小以判断：Excel 的 AI 化，会从"手搭 + 手洗"走向"无头生成 + 三色约定 + Checks + 清洗溯源 一键出"。
第一步永远是 xlsx-author + clean-data-xls + audit-xls 三件套——先把 Excel 造出来、洗干净、查得对。
