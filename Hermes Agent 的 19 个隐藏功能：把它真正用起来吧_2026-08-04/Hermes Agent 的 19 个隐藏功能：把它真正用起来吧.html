Hermes Agent 的 19 个隐藏功能：把它真正用起来吧

 


装完 Hermes Agent，连上 飞书，然后再问几个问题，很多人可能觉得“哦，就这啊，也没啥的”。如果这样子，那么，大概只用到了它三成的功力。

这Hermes Agent是 Nous Research 出的，主打一个自托管、能自我改进的 agent。但大部分人装完就扔那儿了，这篇文章讲的，是剩下那七成功力里真正有用的内容。不是那种“翻翻文档就能发现”的选项，是藏得比较深、很多人大多数人根本不知道存在的功能。

1. 有问题先跑 hermes doctor命令

感觉哪里不对的时候，大多数人的第一反应是打开配置文件一个参数一个参数地抠。 它内置了一个诊断命令，叫 hermes doctor。一条命令帮你把 provider 连接、模型配置、整体环境全部检查一遍，然后直接告诉你哪儿坏了。别一上来就怀疑是模型的问题，先跑这个。

2. 支持OpenClaw 迁移

如果你是 OpenClaw 的老用户，Hermes 在 setup 的时候会自动去找你原来的 ~/.openclaw 目录，然后问你要不要把配置、记忆、技能、API key 全部搬过来。

它还有个 dry-run 模式，让你先看看哪些东西会被迁移，确认了再动手。选项也给你了：可以全部搬（除了 secrets），也可以直接覆盖冲突。说实话，两个差别这么大的工具之间切换能这么无痛，挺罕见的。

3. 支持运行多个后端

本地跑是默认选项，但 Hermes 还支持 Docker、SSH 连远程机器，以及 Daytona、Modal、Vercel Sandbox 这些 serverless 环境。

重点说下 serverless 这几个。它们的逻辑是：你不用的时候就休眠，一个整天闲着的 agent 基本花不了几个钱，但你一发消息，它瞬间就能醒过来。这设计，说实话，有点东西。

4. 迭代预算

每个 agent 都得有个步数上限，不然容易跑飞。但 Hermes 这个预算机制比单纯一个计数器聪明多了：

  • • 预算在父 agent 和它 spawn 出来的子 agent 之间共享
  • • 工具自己内部跑循环的话，跑完了预算会退回去，不会白白扣光
  • • 预算真用完了，会先警告一次、再给最后一次机会，然后强制让它做总结、干净收尾，而不是话说到一半直接暴毙

5. Curator：自我整理技能库功能

这个功能，说实话，大多数人压根不知道。

Hermes 跑久了之后，会攒下一个技能文件夹——就是它自己写的、针对以前解决过的问题的逐步操作笔记。放着不管的话，这文件夹会越来越乱。Curator 会定期跑一轮，然后逐个技能地决定：保留、打补丁、合并，还是归档，判断依据是它们实际被使用的情况。

这玩意儿为什么安全而不是乱来？主要有三个方面：

  • • 只动 agent 自己写的技能，绝不碰你从 hub 安装的那些
  • • 从来不直接删，最坏情况就是归档到可恢复的文件夹
  • • 每次整理前先给整个技能目录拍个快照，回滚一条命令就搞定，而且这个回滚还能再撤销

6. 技能过期,自动归档

一个 agent 自己写的技能，30 天没用就自动标记为 stale，90 天没用就自动归档。这个是硬性规则，不是模型拍脑袋的判断。所以一个技能突然不见了，你永远能知道它为什么消失——这不是玄学，是逻辑。

7. GEPA：定义人类检查点

Curator 和 agent 自己写技能，这些是全自动的，不需要审批。但这里有个所有系统都有的毛病：让 agent 给自己打分，它永远觉得自己干得不错，哪怕实际拉了胯。

GEPA（遗传-帕累托 prompt 进化）是旁边的一个配套项目，解决思路不太一样。它不让 agent 自我评估，而是直接读执行轨迹，搞清楚某个事到底为啥失败，然后通过进化搜索的方式提出具体的重写方案。但注意——每个修改都要跑完整测试套件、过 PR review，才能上线。自我改进没问题，但不是无监督的自我改进。

8. 重要技能禁止删掉

如果你的整个工作流依赖某个技能，跑一个 hermes curator pin，它就不会被自动清理机制归档或移除。平时该打补丁还是能打、该改还是能改，只是保证它永远不会莫名其妙没了。

9.内置信任评分

除了默认的记忆方案，Hermes 还支持一个完全本地的记忆后端，技术上是基于全息降维表示，支持组合式、代数式的查询，不光是普通的 keyword 搜索。

最有用的部分是信任评分：一个事实在多次会话里反复被确认，权重就越来越高；被更新的信息反驳了，权重就降下来。两个记忆冲突的时候，它会把这个矛盾抛给你来解决，而不是自己默默选一个。

10. 不断加深对你的理解

这跟上面说的原始事实存储不一样。Hermes 用了一种叫“辩证用户建模”（dialectic user-modeling）的方法，底层是 Honcho 这个系统。它试图跨会话构建一个关于你的、不断演化的画像，而不是一条条静态的陈述。

区别在哪？ 一个 agent 记得“用户喜欢深色模式”和另一个 agent 正在慢慢建立一套“这人的做事风格是什么样的”工作理论——这俩完全不是一个量级的东西。

11. 用自然语言写 Cron 任务

0 9 * * 1-5 这种东西，不想记完全可以不记。你可以直接跟 Hermes 说“每个工作日早上 8 点给我发一份 AI 新闻摘要”，它就帮你转成真正的定时任务。

一次性延迟任务也行，比如“30 分钟后提醒我”；简单间隔也行，比如“每 2 小时一次”。任务存成纯 JSON 文件，重启不会丢，每次运行的输出也会落盘，随时能翻回去看某一天到底发生了什么。

12. Profiles：一台机器上跑好几个完全独立的 agent

Profile 就是一个完全隔离的 Hermes 实例：自己的配置、记忆、技能、会话、身份文件，全都跟别的实例不共享——除非你在创建的时候明确 clone 一份。

实际用法就是：有人同时跑一个“研究员”profile、一个“开发者”profile、一个“产品”profile，各配各的 Telegram bot，各有各的性格。而不是一个通用 agent 试图同时干所有事。

13. 直接插进编辑器当 agent 后端

Hermes 支持 Agent Client Protocol——就是 Zed 和一些 VS Code 集成在用的那个协议。你可以在编辑器里把 Hermes 当 agent 用，而不是旁边开个聊天窗口。

会话跟当前项目的 working directory 绑定，存在同一个会话存储里，别的会话能接着用。你在编辑器里配的那些 MCP server，也变成 Hermes 在那个上下文里可以调用的工具。

14. Web 控制台

内置一个本地 dashboard，浏览器里打开就行。会话搜索、cron 管理、配置编辑器（表单和原始 YAML 视图都有）、技能管理，全都覆盖了。还支持多 agent 群聊——你可以用 @提及 指定某个名字的 agent 来精确路由消息。

15. 把自己的行为导出成训练数据

这个属于进阶玩法了。Hermes 有个研究模式，可以批量生成 tool-calling 轨迹，worker 数和工具集都可以配置，还跟 Atropos 有集成可以做强化学习。

说人话就是：你 agent 的真实工作历史，能变成 fine-tuning 的数据集。不是每次会话用完就扔。

16. 安全模型

Hermes 能执行自己写的代码，所以它的安全默认值就是按这个风险设计的：

  • • 模型生成并运行的东西，里面夹带的 credentials 会被自动剥掉
  • • 会话之间相互隔离
  • • 容器级沙箱，一个被搞糊涂了或者被攻破的 agent 没法越界访问其他东西

这些不用你自己配置，默认就是这么跑的。

17. 一个订阅，顶替五把 API key

原来你可能要单独搞模型 provider、搜索 API、图像生成、TTS、浏览器自动化，五个 key 来回切换。Nous Portal 把这些全并了：模型访问 + 网页搜索 + 图像生成 + TTS + 云浏览器，一个账号搞定。

当然，你想自己带 key 也完全行。但对很多人来说，光这一条就值了。

18. 技能可以复用

技能遵循 agentskills.io 开放标准。你在 Hermes 里写好的技能文件，可以直接扔进 Claude Code、Cursor 或 Codex，不需要重写。

如果你打算花时间教一个 agent 怎么按你的习惯干活，那这个投资至少不会被锁死在单一工具里——这事值得提前知道。

19. Agent委派

很多多 agent 框架，用之前先得配角色、配路由规则、配消息传递 schema，麻烦得要死。Hermes 呢？spawn 一个子 agent，给它一个任务、给它自己的工具和对话，主 agent 负责协调就完事了。

比如你要同时重构代码、查 API 文档、跑测试套件——三个任务委派出去并行跑，不用自己一个一个按顺序来。
