Hermes Agent的15级玩法：从聊天机器人到7x24小时全自动系统

 

大部分人都是抱着好奇的心态玩 Hermes Agent 的，刚开始的时候，真只把它当个聊天机器人用了。

你问一句，它答一句。关掉标签页，就结束了。这是 Level 1，也是最基础的那种。

但问题是，同一个东西，实际上能玩出 15 个层级。绝大多数人停下的地方，跟它的真实上限，差距大概有从自行车到高铁那么大。

这 15 层拆成三个阶段，每层都踩在前面的肩膀上。你也可以根据自己现在的情况，挑个合适的地方直接起飞。

第一阶段：基础（Level 1-3）

这个阶段，你的 Agent 装好了，只是从“哑巴”变成了“能答话”。

Level 1 —— 一次性的对话

你扔一个问题进去，它吐一个答案回来。没什么特别的。

但很多人忽略了一个关键点：Hermes 不是搜索引擎。 聊天机器人的作用是跟你“聊”，而 Hermes 是直接“干”活的。它能读你电脑上的文件、写代码、跑终端命令、联网搜东西，最后把结果存到你的文件夹里。

区别在你怎么问。“独立创始人该用啥 CRM 软件？” —— 这是问搜索引擎。“研究一下独立创始人最该用的前 5 个 CRM，对比价格和功能，把报告存到我 Reports 文件夹里。” —— 这才是给 Agent 下的任务。

同样的问题，结果完全不一样。三分钟后，文件就躺你文件夹里了。

很多人踩的坑就是：提问方式还跟在 Google 里一样。

Level 2 —— 给它一个“脑子”：SOUL.md 文件

到了这层，这玩意儿才开始有点“人味儿”。

SOUL.md 是一个你自己写的文件，50 到 80 行左右。告诉 Agent 你是谁、做什么生意、客户是谁、利润率多少、偏好是什么、哪些事它绝对不许碰。每次你新建一个会话，它都会自动把这堆东西加载进去。

没有这玩意儿，你问“我该不该涨价？”，它给你发一篇关于定价策略的博客文章。有了它（假设你填上了真实的数据和客户结构分析），它的回答会变成：“你的入门级转化率是 12%，涨 10 美金可能会让 B 类客户流失，而 B 类客户贡献了你 60% 的营收。我建议先在 A 类客户上试试。”

同一条问题，截然不同的答案。

MEMORY.md 和 USER.md 还能跨会话存东西 —— 项目记录、用户偏好、当前上下文。这东西再也不需要每次新开个聊天窗口就让你重新解释一遍所有事。这感觉，跟你每次都要给项目新人重新介绍一遍架构一样。

Level 3 —— 斜杠命令：真正的加速器

大多数用户压根没发现这些命令。说实话，太浪费了。

光是 /background 这一个，就能让你整个会话的效率翻几倍。你在写方案的时候，顺手打个 /background research [竞争对手] 定价和定位。你的主任务继续进行，不用停。五分钟后，一个带着竞品分析的面板直接弹出来。你直接复制粘贴到方案里，思路一点没断。

还有 /queue（当前任务完成后自动执行后续任务）和 /steer（在不打断 Agent 运行的情况下让它换个方向）。这些命令都是真实存在的，真的，值得去翻翻文档。

第二阶段：杠杆效应（Level 4-7）

Agent 开始变聪明了。你渐渐不用再做那些它能干的活。

Level 4 —— 技能，以及技能背后的模型选择

所谓的“技能”，就是知识包，Agent 需要的时候会加载。一个“研究技能”会加载研究方法论；一个“代码审查技能”会加载安全规范。

但真正的解锁点不在于技能本身，而在于把不同的技能路由到不同的模型上处理。网页搜索根本用不着上最贵的模型。DeepSeek V4 Flash 每百万 token 只要 0.1 美元，处理常规研究任务绰绰有余。只有复杂的分析或最终审查，才值得用 Opus 跑。

如果你每月要跑 30 多个研究任务，这里头的成本差距，不是一星半点。

最常见的错误：把贵得要死的 token 花在那些根本不需要它们的任务上。好比开着法拉利去便利店买瓶水。

Level 5 —— 连上你真正的工具箱

MCP 服务器能把 Hermes 跟你的 Gmail、Slack、Notion、ClickUp、GitHub、日历等等工具连起来。到了这一步，Agent 操作的是你自己的私有数据，而不是公开的网页信息。

举个实际的例子：“这周我埋头干活，Slack 里有啥重要事没处理？” Agent 会读取你的频道，按提及和关键话题过滤，再交叉引用你之前设的目标，最后给你一份 10 行的摘要。你不用来回切标签页，不用人工翻 200 条消息。

有一点需要注意：别一上来就一口气连 15 个工具。每多加一个 MCP，模型在每个回合都要多读一些定义。只装上你真正在用的，不用的关掉。

Level 6 —— 并行干活的小弟们

Hermes 能创建独立的子 Agent，每个都有自己的上下文和工具。一个负责研究，一个负责批判。父 Agent 则负责协调和汇总。

真实场景：你需要对三家公司做竞品研究。每个竞品对应一个子 Agent，全跑在 DeepSeek 上。父 Agent 用 Sonnet 把三份报告汇总到一起。十分钟搞定，不是三十分钟 —— 而且某家公司那边结果慢，也不会拖住其他任务的进度。

Level 7 —— 你不在的时候它也干活

这个思维转变，是区分 Level 6 和 Level 7 的关键。

/goal 让你设定一个持续的目标 —— 比如“找到多伦多 100 家诊所，给每家做个落地页，起草个性化的外联邮件” —— 然后 Agent 会自己不停地跑，一个回合接一个回合，直到任务完成或者被你叫停。

Cron 任务就更厉害了。设置一个每天早上 7 点跑的任务。聪明的地方在于一个 wakeAgent 门：一个轻量级脚本会先检查有没有变化。没变化 = 零 LLM 调用 = 零成本。竞争对手更新了定价页面 = Agent 被唤醒，开始研究，然后把简报发到你的 Telegram。这一切在你喝第一杯咖啡之前就完成了。

你不再需要追着问。事情自动发生。

第三阶段：自主运行（Level 8-15）

Agent 自己跑起来，不需要你管了。整个系统会随着时间推移变得越来越强。

Level 8 —— 多个配置文件，各司其职

与其让一个 Agent 试着干所有事，不如建立多个独立的配置文件。一个“侦察兵”配置文件，每隔几小时扫描一次信号。一个“分析师”配置文件，每天上午 10 点综合所有发现。一个“简报员”配置文件，每天早上 8 点把 5 个要点的摘要发到 Telegram。

它们不共享记忆。每个配置文件只用最合适的模型干它自己的那一件事。

你喝咖啡的时候读一下摘要。三个独立的 Agent 昨晚已经帮你把活干完了。

Level 9 —— 越来越聪明的知识库

这个效果得花几个月才能真正体会。

LLM Wiki 技能 会构建一组相互链接的 Markdown 文件 —— 文章、转录稿、研究笔记、会议摘要 —— 你每次喂给它东西，它都会增长。

第一个月：50 个条目，有点用了。第三个月：超过 300 个条目，还有交叉引用。当你问“竞争对手 X 怎么做用户引导？”时，Agent 不仅仅会搜网页。它还会拉出你自己的研究笔记、两个月前一次提到竞争对手 X 的客户对话、以及你上个月索引的一篇文章。单纯靠网页搜索，是找不到这种组合信息的。

Level 10 —— 跨配置文件的看板

一个共享的任务看板，带有依赖链条。一个“建落地页”的卡片会等着“研究 100 家诊所”的卡片完成。依赖关系一清空，Agent 就开始接手干活。

这个对于有 10 个以上分支任务的季度项目来说，非常值得。但对于一个简单的三步流程来说，就有点大材小用了 —— 不需要的复杂度，别硬往上加。

Level 11 —— 语音交互

在 Telegram、WhatsApp 或 Discord 上发一条语音消息。Agent 会转录、处理，然后可以用音频给你回复。

开车去开会的路上：“昨晚的研究里，有什么是我在 11 点电话会议前需要知道的？” Agent 用一段 30 秒的音频摘要回复你。你听着就行，不用看。双手握在方向盘上。

Level 12 —— 浏览器自动化

对于那些没有 API 的网站，Agent 会打开浏览器，导航，提取你需要的信息。比如一个没有公开定价数据的竞争对手：Agent 会打开他们的定价页面，对比你家 Wiki 里上个月的快照，在早间简报里标记出任何变化。

这比直接调 API 慢，也更脆弱。只有在你没有别的办法的时候才用它。

Level 13 —— 把 Agent 暴露成 API

把你的 Hermes 设置暴露为一个 HTTP 端点，兼容 OpenAI 的格式。任何能跟 OpenAI 通信的前端都能连上它。

你的竞品研究变成了一个 API。一个自定义的内部面板可以查询它。整个团队都能在一个实时页面上看到最新的情报。没人需要再打开 Telegram 了。

Level 14 —— 集成到你的 IDE

Hermes 运行在 VS Code、Zed 或 JetBrains 里。你在写定价页面的代码时，顺手问一句：“竞争对手 X 的定价层级是咋搞的？” Agent 会查你的 Obsidian Wiki，拉出你的研究笔记，直接给出答案 —— 你根本不需要离开编辑器。

Level 15 —— 打包成一个可分发的产品

所有东西 —— SOUL.md、技能、Cron 任务、Wiki 结构、连接的工具 —— 打包成一个 Git 仓库。

新团队成员跑一条命令。十分钟内，他们就装好了你的侦察兵、分析师和简报员配置文件，你的 Wiki 结构，你的 Cron 任务，以及你的 SOUL.md 模板。你甚至可以把这个东西发给客户，或者直接卖。

唯一要求：不要在发行包里放 API 密钥。凭据留在每台本机上。仓库承载的是个性化和工作流。用户自己带密钥来。

大多数人的使用现状

Level 1 和 Level 2。

他们写了一个 SOUL.md，把 Hermes 当成一个聪明点的聊天机器人用，每天省下 30 分钟。这也不是说没用 —— 但这大概只是它能发挥潜力的 10%。

从 Level 3 跳到 Level 7，每天节省的时间就从分钟变成了小时。后台任务、异步目标、带 wakeAgent 门的 Cron 任务 —— 这些东西的累积效应，只有你让它跑上一个月才能真正体会。

从 Level 7 跳到 Level 10，Agent 就不再是你“使用”的一个工具，而变成了一个自主运行的“系统”。你只需要检查一下在你没参与的情况下发生了哪些工作。

如果让我重新开始，我会在安装时用 空白模式：除了模型和基本的文件工具外，其他一切全关掉。一次只加一个东西。清楚地知道你打开了什么，以及为什么打开。这是到达 Level 15 最省钱、最可控的方式，不会把钱浪费在你还没想清楚的功能上。
