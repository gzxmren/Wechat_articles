深度使用一个月的DeepSeek Harness，发现跟 WorkBuddy搭配是真的香

上个月deepseek开源了harness工程，我也深度使用了一个月

最大的感受就是是，跟WorkBuddy搭配真的香。

搭配GPT和Claude的模型简直就是灾难

一开始我按照之前的习惯，使用一个Agent时，就想搭配最顶尖的模型

这次也不例外，我一开始折腾也是GPT和Claude的顶尖模型

心想，模型越强，Agent 效果应该越好。

这个想法听起来很合理，大部分的人估计和我的想法一样。

我先接入了 GPT-5.6-Sol，又尝试了 Claude Code Opus 4.8。

成功接入的那一瞬间，我非常兴奋，十分期待Deepseek Harness的表现。

但很快，我发现自己做得最多的事情不是写代码，而是排查接入问题。

最开始，模型会在调用工具时重复申请已经拥有的权限

后来我给了它全部权限，它总是因为沙箱权限不足反复重试

甚至有些时候，工具参数传到了执行器，却因为协议字段不兼容而失败

更让人崩溃的是，模型明明生成了完整的工具调用，Harness 最后拿到的工具名称却是空的

模型还没有开始解决问题，我已经开始解决模型的问题。

我花了太多的时间在顶尖大模型的适配上，以至于一度想要放弃使用Deepseek Harness

直到有一天，我只是让模型读取几个文件、修改一处代码，结果它在权限调用上反复失败。

我看着终端里不断刷新的报错，突然意识到一件事：

我本来是想让 Agent 帮我干活，最后却变成了我在给 Agent 做适配。

用Deepseek Harness搭配Deepseek-v4-flash可以吗？

Deepseek Harness既然是Deepseek开源的，而我有WorkBuddy的订阅

WorkBuddy又有Deepseek自家的Deepseek-v4的模型，价格还很便宜

为什么我不把WorkBuddy接入Deepseek Harness呢？

所以我没有继续死磕 GPT 和 Claude 接入的报错了

而是试着把 WorkBuddy 里的订阅接入到 DeepSeek Harness。

这里，我用到的插件是社区提供的 dsh-connect-workbuddy

安装完这个插件后，Deepseek Harness可以直接复用Workbuddy的登陆态，直接可以在 Deepseek Harness 的里切换模型。

我以前用其他harness得agent，很多时候真正麻烦的是接入。

比如用Codex接入Deepseek-v4-flash，需要下载第三方软件，或者改配置，这个步骤就劝退好多人

并且，模型接口、API Key、网关、协议、权限、上下文长度、工具格式，每一层都可能出问题。

而Deepseek Harness的插件能力，让社区的开源插件可以直接拿来用

Deepseek Harness + Deepseek-V4-flash = 起飞

WorkBuddy 接进来之后，我主要使用的是 DeepSeek V4 Flash。

前几天更新了V4.1，而且现在还在打折阶段，我也是换成了Deepseek-V4.1-Flash

搭配起来的效果是真的不输GPT和Claude的顶尖模型

它虽然不是现在市面上最强的模型，但是它是在我体验后，在 DeepSeek Harness 里跑起来最顺的模型。

我一般用Deepseek Harness写代码，这就涉及到一连串的连续动作

读取项目文件，理解目录结构，定位问题，修改代码，执行测试，根据报错继续修改，最后再检查一遍结果。

这种任务最怕中途断掉，一旦断掉，就token浪费了不说，还浪费时间。

模型如果只会回答，却不能持续调用工具，最后还是要我自己接手。

但 DeepSeek Flash 在Deepseek Harness里使用的感觉，是它更愿意沿着这条链路一直走下去。

它的速度也比较适合这种多轮调用。

现在最新版的Deepseek Harness兼容了GPT和Claude模型调用

社区的插件也可以直接复用Codex和Claude登陆态

所以我现在的用法很简单

日常的代码修改、文件整理、项目理解、快速原型，我优先使用 DeepSeek Flash。

遇到特别复杂的推理任务，或者需要换一种思路时，再切换到 GPT 或 Claude。

这和以前最大的区别是，以前每出一个强大的模型，都要直接用它官方的Agent，如果没有就要想办法接入

而切工具，则是最麻烦的事情，现在我不需要为了换模型，重新换一套工具和配置。

模型变成了工作流中的一个按钮，而不是一个新的工程项目。

我觉得这也是 WorkBuddy 和 DeepSeek Harness 组合起来最舒服的地方：

Harness 负责把 Agent 跑起来，WorkBuddy 负责让我方便地使用不同模型。

Harness = Agent + Model

以前模型发布的时候，我总是习惯看排行榜，然后选择最强/次强的模型。

但这次折腾 DeepSeek Harness，让我开始重视另外一件事，Harness工程也是最终表象的重要一环。

最近看到斯坦福和MIT共同发表了一篇论文，把同一个模型放进不同的 Harness 中执行同一批软件工程任务。

他们的研究表明，同一模型换个 Harness 能产生约 6× 的性能差距。

论文地址我也放到这里，大家有兴趣也可以看看。

https://arxiv.org/abs/2603.28052

这也解释了我自己的体验：为什么同一个 GPT 接进 Harness 时让我不断排查问题，而 DeepSeek Flash 接进来后却更像一个完整的 Agent。

总结

DeepSeek Harness 只是所有Harness工程的Agent的一个，它或许不够完美

但是我觉得对我来说，可能是最方便的，它给了我一套可以持续执行任务的工作流。

而WorkBuddy现在每天签到会送100积分，轻度使用的话，是完全没问题

积分不够，走订阅，也是比直接走官方模型便宜

DeepSeek Harness + WorkBuddy，是真的香。
