外网跟着玩疯了，只因 Karpathy 做了个《指环王》实验。

前几天，我介绍了卡帕西用 Claude Opus 5 制作《指环王》3D 短片的实验。

他把小说第一段交给模型，给了 100 万 token 的预算，成本大约 10 美元。

Opus 5 自己跑了两个小时，写出约 5500 行 Three.js 代码，搭场景、摆人物、设计镜头，再把它们做成一段 90 多秒的《指环王》动画。

成品有点粗糙，卡帕西自己也说里面留下了不少问题。

但一段文字经过几个小时，真的变成了一个可以运行的 3D 世界，这件事还是挺新鲜的。

几天后再去看原帖下面的引用，开发者们已经开始集体交作业了。

《星球大战》《哈利·波特》、复古游戏、可玩场景陆续冒出来，甚至有人专门研究，换一个 Agent Harness 到底能让结果提升多少。

01

《星球大战》开场，Opus 5 连做了 8 小时

这一批跟做项目里，最抢眼的应该是 ChrisGPT 的《星球大战：新希望》。

开发者把电影开场交给 Opus 5 Max，让模型用 Three.js 做成 LEGO 风格。

Opus 5 连续工作约 8 小时，自己制作飞船、角色和 SVG，处理镜头、剪辑与配音，最后交出一段 5 分钟左右的完整开场。

卡帕西的原版更像短篇实验，这个版本已经开始处理连续剧情和多场景调度了。

X 原帖：https://x.com/ChrisGPT/status/2084371255092768817

02

同一个玩法，换成《哈利·波特》

另一个开发者把《哈利·波特》的开头交给了 Opus 5，最后得到一部约 4 分钟的程序化电影，以及约 7600 行 TypeScript 代码。

这个版本没有使用外部美术素材。

纹理由运行时的 2D Canvas 绘制，人物靠立方体、圆柱等基础几何体组合，声音则由 Web Audio 合成。

画面谈不上精致，但整套东西都由代码生成，完成度挺出人意料。

X 原帖：https://x.com/filicroval/status/2083875012243542162

03

把卡帕西的《指环王》重做了一遍

还有人沿着卡帕西《指环王》相同方向重新做了《A Long-Expected Party》。

Opus 5 在 Claude Code 中工作约两个小时，把故事、场景、转场、镜头和程序化世界写进一个 HTML 文件。

这次人也参与了过程。

开发者提供草地制作参考，并要求模型持续检查画面。随后又补上旁白、音效和音乐。

最终版本可以在线运行，源代码也放到了 GitHub。

X 原帖：https://x.com/MengTo/status/2084330375527145801
在线体验：https://mengto.github.io/a-long-expected-party
开源地址：https://github.com/MengTo/a-long-expected-party

04

生成的世界真的能玩

有人使用 Thrixel 做了一个可玩版本。

她只给 Claude 一个 /goal 提示，模型随后通过 Thrixel MCP 创建和迭代 3D 资产，组装场景，再把游戏逻辑接起来。

前面的不少项目更接近代码生成的 3D 电影。

Thrixel 这个版本已经能够让人进入场景操作，开始向真正的游戏靠近。

X 原帖：https://x.com/RanaHanocka/status/2084697216816447510

05

重做一款你怀念的老游戏

开发者 Fei Xia 给 AI 的任务很有意思：生成一款自己最怀念的游戏。

他特意说明，视频中的内容全部由程序化方式生成，自己也不满足于只做一段镜头，希望把它真正做出来。

比起复刻某个知名 IP，这个方向更贴近个人需求。以后你可能会让模型临时做一款童年游戏，只给自己和几个朋友玩。

06

Opus 5、Three.js 和 Blender 连续做七天

有一个开发者花了七天，把 Opus 5、Three.js 和 Blender 组合起来，又使用了 Synty 与 bocdagla 的现成资产。

这个项目用了成熟的外部资产，也把 Opus 5 放进了已有的 3D 生产流程。

作者说还有很多细节需要打磨，但目前的结果已经很有希望。

多个 AI 工具拼出互动故事

再用 Runway Aleph 给 3D 世界换一种画风

有人用 Runway Aleph 对这类 3D 动画做了视觉重绘。测试没有使用图片参考，主要依靠提示词控制效果。

09

Opus 5 还能被推得更远

开发者 Oliver Johansson 也引用了卡帕西的实验，并放出一段 3D 短片。

他认为 Opus 5 还有更大的发挥空间。

这条帖子没有公开提示词、成本和具体代码，暂时很难做技术对比。

它更像这场接力中的另一份作业，也说明开发者已经开始主动寻找 Opus 5 的能力边界。

X 原帖：https://x.com/oliverjohansson/status/2083986730890465751

还有一个是 Izkimar 做了一组很有意思的对照：同样的模型、同样的预算，换一套 Agent Harness，再看谁做得更好。

模型名称相同，任务拆分、上下文管理、工具配置和检查循环不同，成品依然可能拉开明显差距。以后看 Agent 能力，只报一个模型名字已经不太够了。

看完上面这些 case ，大致能看到三条路线。

第一条是程序化电影。

《星球大战》《哈利·波特》和改进版《指环王》，都在尝试把一段文字扩展成连续的 3D 叙事。

第二条是长时间运行的 Agent。

有人增加 token，有人更换 Harness，测试模型能不能围绕一个目标稳定工作几个小时。

第三条是可玩世界。

Thrixel 已经把 3D 资产、场景和玩法接了起来，复古游戏实验也在追求真正运行的世界。

Blender 项目则展示了模型与现成资产、传统 3D 工具结合的可能。

目前最明显的短板，依然是模型不会高效验收自己的作品。

它可以写几万行代码，却很难像真人一样完整看完视频、进入游戏四处走动，再把穿模、碰撞和节奏问题逐个修掉。

卡帕西的原始实验里，Opus 5 只能缓慢地截取画面进行检查，所以最后留下了不少问题。

等模型能够流畅观看视频、操作游戏并自动测试，这类项目的完成度还会再上一个台阶。

前几天，《指环王》还只是卡帕西的一次实验。几天后，它已经变成了一场公开接力。

下一次再出现类似的推文，大家交出来的可能就是一款真正可以玩的游戏了。
